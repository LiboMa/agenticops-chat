  • 3 nodes: 2 chaos-lab workers + 1 dedicated tainted node (dedicated=agenticops:NoSchedule) hosting only the app — chaos can never evict it.
  • Two identities: IRSA (AWS read + bedrock:InvokeModel) to perceive; in-cluster ServiceAccount kubeconfig + scoped RBAC for the kubectl fix path.
  • No NAT gateway (account EIP quota was full) — nodes use public subnets via IGW. No public ingress — sole access is a kubectl port-forward tunnel.

3. Methodology

Per scenario: restore baseline → inject fault (existing chaos/*.sh) → seed perception (POST CloudWatch alert to /api/webhooks/alert/cloudwatch) → assert four phases via REST polling → restore on teardown. Fully autonomous: auto_rca + auto_fix + auto_approve_l0_l1 on, HITL off.

6. Issues Found & Fixed During the Run

  1. EIP quota exhausted — us-east-1 had 12/5 Elastic IPs in use. Disabled NAT; nodes use public subnets via IGW (also cheaper). 2fecdf6
  2. EKS version retired — k8s 1.29 no longer creatable, eksctl 0.189 caps at 1.30. Pinned 1.30. 2fecdf6
  3. Orphan resources — a Feb-2026 half-deleted cluster left 3 CFN stacks + VPC + a stuck Classic ELB + ENI + 2 SGs, blocking recreation. Cleaned up (user-approved).
  4. App eviction risk — single-replica app could be evicted by node-drain/stress. Dedicated tainted node + chaos scoped to chaos nodes. 8389c57
  5. Local port collision — a pre-existing local uvicorn held :8000, so port-forward silently bind-failed and requests hit the wrong app (spurious 401s). run-e2e.sh now auto-selects a free port & verifies a real login through the tunnel. 059f8af
