# AgenticOps（agenticops-chat）分享
我近期要对 AgenticOps 做一个 Team 内部（架构师团队）的分享，介绍项目、架构与功能。以下是大纲，请以此为主线生成 html 的 Presentation，时间约为 10-15 分钟；有时间还可以 Demo。
仓库：https://github.com/LiboMa/agenticops-chat.git

## 1. 背景与定位
1. AgenticOps 是什么：Agent-first 云运维平台——一支 AI 智能体团队扫描 AWS 基础设施、发现问题、定位根因、规划修复，低风险问题自主修复，并在每次运维中学习；
2. 解决谁的问题：SRE / 平台 / 云运维团队，要的是「告警 → 根因 → 修复」全闭环的 on-call 副驾，而不是又一个看板；

## 2. 演进过程
1.0.0（2026-03）首个 MVP：7 智能体 + 自动修复流水线 + Web 看板 → 1.1 自优化记忆与自主技能 → 2.0 受治理的自主、多云能力层 → 2.2 Signal Gate 降噪与 RCA 质量门 → 2.5 云安全审查 → 2.6 变更管理（ITSM）、图事实 + RCA 定位 → 2.7 蓝白工作台 + 核心信任加固（进行中）

## 3. 架构（直接上干货）
### 总体架构
- 三入口（CLI `aiops chat` / Web 看板 / IM 机器人）→ Main Agent（纯路由）→ 6 个专家智能体（Scan、Detect、RCA、SRE、Executor、Reporter）→ AWS
- 共享层：Agent Memory、Agent Skills、Security Engine、SQLite / PostgreSQL、MCP Servers
### 设计原则
- 智能体即工具；读 / 规划 / 执行相互隔离（只有 SRE 规划、只有 Executor 执行；L0/L1 自动批准，L2/L3 人工审批）
- 分层模型控成本；智能体安全地学习；配置单一真源；默认从简
### 关键流程
- 自动修复流水线：告警 → HealthIssue → RCA → SRE → 审批 → Executor → 验证 → 解决（9 态生命周期）
- 双告警入口（Webhook / IM Agent）+ Signal Gate 去重降噪
- 变更管理（ITSM）：Main → SRE 合法性审核 → 审批 → Executor，不需要 HealthIssue
- 自学习层：记忆与技能写入先落草稿，经安全门禁发布，人类撰写的知识被固定

## 4. 功能
- 运维闭环：Scan、Monitor & Detect、Signal Gate、RCA、自动修复、变更管理
- 安全与知识：云安全审查（CIS 评分、三态可达性）、知识库、报告与定时任务
- 平台与集成：Web 看板 / CLI / REST API、Messaging（飞书 / Slack / 钉钉 / 企微…）、MCP、图引擎、Galaxy（实验性）
- 部署形态：本地 pip / Docker / 一键 AWS 开发沙箱（deploy-sg）/ Terraform 生产栈（ec2 / ecs / eks，仍为脚手架）

## 5. Demo（可选）
1. Chat：用 `aiops chat` 或 Web Chat 巡检账号、提一个问题；
2. 事件闭环：一个 Issue 从诊断、方案、审批执行到验收；
3. 变更管理：一张变更单从申请、审核到执行与审计；
4. 云安全审查 / Galaxy 关系图；

## 6. 总结一下：
我想阐述的核心点：
1. 第一、Agent-first 的运维闭环可行：从告警、根因到修复，低风险问题自主完成，有 EKS 实验室 10 个故障场景的闭环验证做支撑；
2. 第二、自主与安全不矛盾：读 / 规划 / 执行隔离、风险分级审批、fail-closed 校验，让「敢把运维交给 Agent」有工程保障；
3. 第三、系统越用越好：记忆、技能、知识库在安全门禁内自优化，运维经验沉淀为组织资产；
4. 第四、落地路径清晰：本地、Docker、一键 AWS 沙箱已跑通，Terraform 生产栈待验证，可按客户成熟度逐级交付。
