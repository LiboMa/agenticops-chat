## N1 三种最常用的简报（2026-11-17）

### 做了什么

| 条目 | 改动 |
|---|---|
| 批准（问题的修复方案） | 一页里：为什么（诊断、它引用的证据、模型自己的把握、另一个模型的复核、位置是否核实）、打算怎么做（每一步的说明、命令、代码分的类；回滚）、会碰到谁（关系图的三个数）、做完怎么算成（声明的检查项）。动作：按住 `A` 批准、`R` 退回方案、`D` 忽略，后两个必须写理由 |
| 按住批准 | 按下时记住目标（哪件事、哪份方案、内容哈希），到时只批准还在屏幕上的同一个目标；中途松手、按了别的键、切走窗口、换到另一件事，都不批准。批准带的是你当时看到的内容哈希，方案在你看的时候变了会被服务端拒绝（409），页面说明并重新取 |
| 批准之后会不会执行 | 按钮和开头那句话跟着服务端的 `available_actions` 走：执行器和自动修复都开着才是「按住批准并执行」，否则是「按住批准」，并写明不会自动执行。服务端不放行时按钮不可用，开头那句话写明原因 |
| 验收 | 做了什么（几步、用时、按哪一版方案执行、和批准时是否一致、为什么要人看）、代码已经核对过的检查、要你看一眼的检查。`X` 逐项打勾，全部打完 `A` 才可用；勾过的检查项随验收记入审计。`R` 不通过，要写理由 |
| 确认诊断 | 诊断和三块可信度，加一句为什么没有自动出方案（把握低于门槛 / 被复核否定）。四个选项就是产品现有的四个：`Y` 对、`P` 位置只对了一部分（只有位置能评的时候才有）、`N` 不对、`F` 误报；后两个必须写理由。`M` 让它重新诊断 |
| 证据速览 | 空格打开，`←` `→` 换一条，`Esc` 关。只显示诊断时存下的类型、出处和摘要，并写明原始输出没有保存 |
| 做完一个决定 | 这件事立刻离开队列，下一件接上；它如果以另一种情形回来（批准了但没开始），会重新出现 |
| 后端：`step_tiers` | 方案的响应多一个只读字段：每一步的命令由代码分的类（`write` / `readonly` / `blocked` / `unknown`，没有命令的一步是 `unknown`）。用的是自动批准下限已经在用的那个分类函数；出响应时现算，不存库，不进内容哈希，更新接口不接受它 |

### 和设计稿不一样、照实做的地方

- 没有「要求修改」：`R` 是「退回方案」。方案被标为已退回，这件事以「方案被退回」回到队列。
- 没有 5 秒撤回：决定立即生效。所以批准要按住，说「不」都要写理由。
- 「对」之后不会自动出方案：这件事留在原处，变成「生成方案」那一页（N2）。
- 忽略：理由先作为备注写进时间线（现有接口不保存忽略的理由），并写明检测 agent 会记一条「这件事被人忽略过」。
- 误报、不对：页面写明后果（误报 = 忽略 + 检测 agent 记下这一类；不对 = 这次诊断标为不正确）。实测这两种判断各会写一份 agent 记忆。
- 很长的诊断先显示六行，「展开全文」看全部。

## N2 其余简报、变更单、agent 在做的事（2026-11-17）

到这一阶段，接口可能给出的 16 种组合每一种都有自己的一页（测试 `newuiRegistry` 对着共用清单逐行核对）。

### 做了什么

| 条目 | 改动 |
|---|---|
| 执行失败 | 说清楚是哪一种：某一步失败（第几步、它报了什么）、步骤做完但有检查没通过、还是验收时被人判为不通过（引用那句话）；回滚做了几步、有没有失败。`A` 重新出方案、`M` 重新诊断、`D` 忽略 |
| 批准了没开始 | 为什么没开始（执行器关着 / 没排上）、当初批准的那一版和它的哈希、内容之后变没变。`A` 按住重试；服务端不让执行时按钮不可用并写明原因。`R` 撤回批准（问题）/ 撤销变更单（变更） |
| 方案被退回 | 谁退回的、写了什么、被退回的那一版。`A` 按这条意见重做 |
| 诊断被否 / 没有诊断 | 人的判断（谁、什么时候、写了什么，取自时间线）和被否的诊断。`A` 重新诊断 |
| 诊断已确认 / 过了门槛没人确认 | 诊断和人的判断；后一种写明「自动修复关着，所以没有人去请 agent 出方案」。`A` 生成方案、`M` 重新诊断 |
| 等收尾 | 执行结果和代码核对过的检查；没有留下结论的执行照实说。`A` 标记已解决 |
| 变更：草稿 | 要改什么、谁提的、对上了哪些资源、哪些名字没对上、提的人自己写的步骤。`A` 开始审核、`R` 撤销 |
| 变更：审核要澄清 | 审核提的问题一题一格；后端只收一段话，页面把回答按题号合成一段发出 |
| 变更：待批准 | 要改什么、审核怎么说、实施方案、会碰到谁、检查项。后端要求批准带理由：先写理由，再按住批准；没写理由就按，焦点会跳到理由框。`D` 拒绝 |
| 变更：待验收 | 和问题的验收同一套打勾；`A` 确认完成、`R` 判定失败 |
| agent 在做的事 | 待决右边一栏：现在在做的每一件（做什么、做了多久、是哪件事），超过它自己的超时会标「可能卡住了」；下面是最近做完的几件。数据来自新接口 `GET /api/ui/activity` |
| 交给 agent 之后 | 简报顶上一行「agent 正在诊断 / 出方案（几分钟前开始，由谁发起）」，按钮不可用。这是服务端的记录：刷新、换浏览器、换人看到的都一样 |

### 后端

| 条目 | 改动 |
|---|---|
| 请 agent 做的事有记录、不会重复开始 | `POST /api/health-issues/{id}/rca` 和 `…/generate-fix-plan`（以及 `/api/issues/…` 两个别名）：开始前先占住这件事（`services/agent_runs`，进程内，一件事同时只有一个人请来的 agent），已经有一个在做就回 409 `agent_run_in_flight`（带是哪个 agent、几点开始、谁发起）；线程结束时释放，线程没能起来也当场释放，超过 RCA 看门狗的时限（`rca_timeout_seconds`）视为放弃，不会永远卡住。时间线上记 `rca_started {trigger: manual, requested_by}` / `fix_plan_requested`，agent 出错记 failed |
| `GET /api/ui/activity` | 现在在做的 / 接下来的定时任务 / 最近一天做完的。只用核实得了的状态：人请来还在跑的 agent、`investigating` 和 `fix_executing` 的问题、pending / running 的执行、已批准且时间线上执行已开始未结束的方案、审核中和执行中的变更、正在跑的定时任务、正在构建的关系图。`open` 的问题不算。每条带 `since`（没有记录就是空）、`basis`（怎么知道的）、`overdue`（超过自己的超时）。任何登录用户可读，固定次数的查询，不调模型也不调云 |
| 忽略的理由不再丢 | `PUT /api/issues/{id}/status` 的 `note` 以前收了不存（时间线写的是「anomaly status update」）；现在它就是状态变更的理由，也写进检测 agent 的那条备忘。理由上限从 500 字提到 2000 字 |
| 退回的理由交到 agent 手上 | 重新出方案时，如果最新的方案是被人退回的，那句理由会放在 `<reviewer_feedback>` 里交给 SRE agent（`agents/sre_agent.rejection_feedback`）：注明这是要回应的信息、不是改变协议的指令，引用里的结束标签会被处理掉；代码做的退回（内容在批准后变了）不算 |

## N3 经过页（2026-11-17）

简报只问一个决定；经过页是这个决定背后的全部记录。地址是 `/app/new/story/I12`（变更是 `C3`），可以直接打开、可以收藏。

### 做了什么

| 条目 | 改动 |
|---|---|
| 进入和返回 | 在待决里按 `Enter`，或点简报第一行的「经过」；「X 现在不在等你」那一页也有「看它的经过」。`Esc` 或页面上的返回回到原来的地方（同一件事、同一个筛选），和浏览器的后退是同一步。直接打开的地址没有来处，返回去待决 |
| 状态行 | 后端状态的中文名、在等谁、等了多久、账户和区域。「在等你」只在这件事真的在你的队列里时才说，否则是「在等人处理」；「agent 在处理」只在服务端有记录显示它在做时才说，否则是「轮到 agent，但没有记录显示它已经开始」——几百件 `open` 的问题就是这种；超过自身时限的写「可能卡住了」 |
| 需要你 | 这件事在等你时，写一句要你做什么，`Enter` 或「去决定」回到它的简报。账户范围选的是别的账户时，范围会换成这件事所在的账户并提示（否则待决会说它「不在等你」） |
| 六步 | 问题：发现、诊断、方案、批准、执行、验收；变更：申请、审核、方案、批准、执行、验收。停在哪一步、哪一步出了问题，用的是旧版页面自己的判断（`lib/issueDetailModel`、`lib/changeDetailModel`），两个界面不会说法不一。还没到的步骤只有名字 |
| 每一步写什么 | 发现：来源、同样的信号出现过几次、描述。诊断：结论、证据（可以打开看）、三个可信度、人的判断和那句话、为什么没有自动出方案（把握低于门槛，带两个数；或复核否定）。方案：版本、哈希、几步、其中几步会改动、几步分不了类；每一步和回滚收在折叠里；被退回的写明谁、什么时候、理由。批准：谁、什么时候（变更带批准理由）。执行：每一次执行一行（状态、几步报告成功、用时），步骤收在折叠里，失败时写它报的错、没通过的检查、回滚了几步、验收时谁怎么说。验收：在等什么，或者谁什么时候标记了解决 |
| 被忽略 / 被拒绝 / 被撤销 | 在它停下的那一步写明，并引用当时写的理由（谁、什么时候）。服务端在没人写理由时填的那句「anomaly status update」不当作人的话引用。被忽略的问题可以在这里「重新打开」 |
| 方案和诊断对不上时 | 方案依据的是更早的一次诊断，或者方案的记录比它依据的诊断还早（草稿被改写过、改写时间没有记录）——都写明，批准简报上也写。后一种情况不显示方案的创建时间，免得读成「先出方案后诊断」。在真实数据里各有几件 |
| 全部记录 | 时间线上的每一条，用旧版页面的句子，收在折叠里 |
| 事实和备注 | 右边：后端状态的原名、旧版页面的那几行事实、去旧版页面的链接。问题可以追加备注（`Enter` 发送，`Shift+Enter` 换行，输入法组字时不发；在框里按 `Esc` 只离开输入框）。备注只能追加。变更单没有备注接口，所以不显示 |
| 证据 | `Space` 打开第一条证据，`←` `→` 换，`Esc` 先关证据再返回。证据面板的状态抽成了待决和经过共用的一段代码 |

## N4 现场页（2026-11-17）

「现在谁在做什么、做了多久」。地址是 `/app/new/live`，打开某一条是 `/app/new/live/I12%3Adiagnosis`。数据是 N2 的 `GET /api/ui/activity`，后端只多了一处（见下）。

### 做了什么

| 条目 | 改动 |
|---|---|
| 四组 | 左边一栏：**现在在做**（人请来还在跑的 agent、诊断中 / 执行中的问题、进行中的执行、审核中 / 执行中的变更、正在跑的定时任务、正在构建的关系图）、**停住了**（诊断已经结束、没有留下结果，状态却还停在「诊断中」——没有 agent 在做它，也不在任何人的待决里）、**接下来**（排定的定时任务）、**最近一天做完的**（诊断、方案、执行、定时任务，带结果：做完了 / 失败 / 等你看）。每条写谁在做、做什么、做了多久；超过自身时限的标「可能卡住了」。视角标签「现场」旁边是真正在做的条数（停住的不算） |
| 打开的一条 | 服务端是怎么知道它在做的（有人请的 / 有进行中的执行记录 / 只凭状态 / 时间线上开始了没结束 / 定时任务 / 构建），几点开始，是否超时；然后是这件事时间线上最新的 8 条记录 |
| 做的过程 | 后端不记录 agent 的每一步，执行器也要到结束才写每一步的结果——页面照实写。执行中的显示它在执行的方案（不标进行到第几步）；做完的显示结果：诊断的结论和证据、方案的每一步、执行的每一步和验收 |
| 做完之后 | 停在一条正在做的事上时，它做完了地址会自己换到它留下的结果（同一件事、同一种工作里最新的一条），并写「它做完了。下面是它留下的结果。」；没有对应结果、或者已经超过一天的，写「这一条已经不在列表里了」，可以去看它的经过 |
| 取不到 | 刷新失败时保留上一次的内容、整体变暗，顶上写「最新的动态没取到。下面是 HH:MM UTC 取到的」，可以重试；从来没取到过就是「没取到数据——这不代表现在没有 agent 在做事」 |
| 键盘和手机 | `J` / `K` 换一条，`Enter` 看那件事的经过（`Esc` 回到同一条）；手机上列表和打开的一条二选一，有「回到列表」 |
| 和别处的连接 | 待决右边一栏的每一条点开就是这里的那一条；经过页的状态行在 agent 正在做这件事时多一个「看现场」；这件事在等你时，打开的那一条上有「去决定」 |

### 和设计稿不一样、照实做的地方

- 设计稿有给 agent 插话、暂停、叫停并回滚、撤回决定。后端都没有，所以没有这些控件，也不写「连接 / 实时」——写的是「每 10 秒刷新」。
- 设计稿的步骤条（每一步一个格子、正在做的那一格闪）没有做：没有「进行到第几步」的记录。
- 真实数据里有两件问题的状态停在「诊断中」79 天和 42 天。前一件时间线上只有诊断开始、没有结束：列在「现在在做」，标「可能卡住了」。后一件时间线上诊断已经结束（没有结果）：列在「停住了」，写明没有 agent 在做它。这两件都不在任何人的待决里——这是产品的缺口（诊断没有结果时状态没有退回去），列在「之后」；现场页至少让它们看得见。
