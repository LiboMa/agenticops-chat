# Chat 改版：ChatGPT 风格 + Codex 式工作过程 + 富渲染（设计）

2026-11-07 · 主人在浏览器草图里确认了布局与附件效果 · 做在 `MVP-2.7.1` 分支上（基线 `cd4f0d2`，主人决定），记进 `docs/MVP-2.7.1-RELEASE.md`，随 2.7.1 发布

## 为什么

主人要 Web 的 Chat 用起来像 ChatGPT / Codex：

- 回答能直接看图（柱状图、饼图、趋势图）、看流程图，而不是模型画出来的 ASCII 字符画。
- 能看到 agent 正在做什么。
- 拖进来的文件一眼可见。
- 手机上也能用。

现在的 Chat 有三处不足：

- 工具调用只显示成一排名字小标签。
- 流程图是 ASCII，图表只能靠文字描述。
- 附件排在输入框外面，拖拽只认底部那一小块。

## 主人已确认的

1. **布局选 B**：ChatGPT 风格的单栏对话，左侧是对话列表，每个回答上方有一个 Codex 式的「工作过程」块。
   - 品牌用 AgenticOps 自己的，不复制 OpenAI 的标志、图标和文案。
2. **结尾给「下一步」建议**：放在回答操作栏的下面，点一下就作为新问题发送。
3. **正文直接渲染**：
   - markdown 表格；
   - 柱状图、饼图、趋势图；
   - 流程图，不能是 ASCII；
   - 图片可以点开大图预览。
4. **附件放下后的样子**（草图 `attach-drag.html` 右侧）：附件进到**输入框里面**。
   - 图片是方形缩略图，上传中显示圆形进度，悬停出现 ✕。
   - 文档是带类型色块的卡片（PDF 红、Excel 绿、Word 蓝、PPT 橙）；处理中和失败的原因直接写在卡片上。
   - 被拒的文件标红，写明原因。
   - 底部显示「n / 20 · 已用 / 上限」计数。
   - 上传或处理完成前，发送键是灰的。
5. **Web 端和移动端都适配**，主人原话「自动做好」。
6. **其它不变**：附件的后端、按模型交付的规则、历史预算、上传配置都保持现状。

## 我的判断（主人可以改）

**拖动中的提示**
- 整个对话区都能接住拖进来的文件，不必对准输入框。
- 拖动时只给一层很淡的提示（虚线边框加一行「放下即可添加」），不遮挡内容。
- 主人确认了「放下后」那张，对「拖动中」那张没表态。

**页面骨架**
- 在 Chat 页，全局导航收成一条可展开的细图标栏。
- 现在的 SessionFlyout 改成固定在左侧的对话列表，内容依次是：新对话、搜索、按「置顶 / 今天 / 昨天 / 7 天内 / 更早」分组。
- 对话列表在桌面端可以收起，在移动端是抽屉。
- 其它页面的导航不变。

**图表的数据格式**
- 主 agent 用 fenced 代码块输出图表：
  ````
  ```chart
  {"type":"bar|line|area|pie","title":"…","x":["周一",…],"series":[{"name":"告警","data":[12,…]}],"unit":"条"}
  ```
  ````
- 前端用已有的 recharts 渲染，不新增图表库。
- JSON 解析失败或字段不对时，原样显示代码块，并加一行「图表数据无法解析」。

**流程图**
- 用 ` ```mermaid ` 代码块输出。
- 前端用 mermaid 渲染：新增依赖，只在出现 mermaid 块时才懒加载，`securityLevel: "strict"`，不执行任何脚本或链接。
- 渲染失败时回退为代码块。
- 渲染出来的图可以点开放大，复用附件的大图预览框。

**提示词**
- 规则只在 **Web Chat** 生效：
  - 有统计数据时用 `chart` 块；
  - 有流程或调用关系时用 `mermaid` 块；
  - 不画 ASCII 图；
  - 规则按概念类别写，保持云中立。
- 生效范围：
  - Web Chat 的完整版和只读版（viewer）主 agent 提示词都加这条规则。
  - `create_main_agent` 增加一个开关来控制；Web 的会话缓存把开了和没开的 agent 分开存。
- 不加规则的地方：
  - CLI、IM 机器人（飞书 / Slack）和定时任务（AgentChain）照旧，所以飞书消息和定时邮件里不会出现图表 JSON。
  - 报告（reporter）不加：报告要导出成 HTML / PDF / 邮件，那条链路不渲染这两种块。
- 存为报告：Web 回答里的 `chart` / `mermaid` 块按原样作为代码块存进报告，报告页和导出都不渲染。

**回答里的图片**
- 模型拿不到附件的地址（交付清单里只有文件名、类型和交付方式），所以回答里不会出现本站附件图片。
- 「图片预览」指两处：
  - 用户消息里的缩略图，现在已经能点开大图，保持不变；
  - 输入框里的新缩略图，同样能点开。
- 回答里的 markdown 图片一律显示为链接，不自动加载外站地址，以免泄露访问者的 IP。
- 图表和流程图可以点开放大。

**工作过程块**
- 后端改动：
  - `tool_start` 增加 `summary`：工具输入的一行摘要，例如命令或资源 id。
  - `tool_end` 增加 `duration_ms` 和 `result_preview`：结果的前 200 字左右。
  - `tool_start` 还记下 `text_offset`：这一步开始时，回复文本已经写到第几个字。
  - 这几项都写进 `ChatMessage.tool_calls`，刷新后照样能看到。
- **脱敏**：
  - 摘要和结果预览先过现有的 `redact_secrets`，再过一层**只用于显示**的更严过滤，盖掉：
    - `--password` / `--secret` / `--token` 一类参数后面的值；
    - `aws_secret_access_key` 等配置值；
    - `Authorization: Bearer …`；
    - URL 里的 `user:pass@`。
  - 共用的 `redact_secrets` 不改：它守着所有数据库列，主人要求它重精确。
  - 显示用的预览多盖一些，只是少看几个字。
- **步骤之间的过程话**（模型在调用工具之间写的「我先查一下……」）：
  - 按 `text_offset` 切开：最后一次工具调用之前的文字放进工作过程块，按时间穿插在步骤之间（Codex 的做法）。
  - 最后一次工具调用结束后的文字是正文。
  - 如果模型先写完答案、最后才调一次工具（这段之后没有文字），就把最后一段非空文字当正文，它不再出现在工作过程块里。
  - 旧消息没有 `text_offset`，照旧整段当正文。
- 前端行为：
  - 运行中展开，实时追加步骤，每步带耗时和状态图标（运行中 / 成功 / 失败）。
  - 完成后收成一行「已处理 N 步 · T 秒」，点开能看每一步。
  - 子 agent（scan / rca / sre 等）和 `enhanced_task` 都算作一步，不展开它们的内部。
- 只显示工具步骤和过程话，不显示模型的思考文本（reasoning）。

**回答操作栏**
- 有三个操作：
  - 复制，复制 markdown 原文；
  - 重新生成：
    - 只出现在最后一条回答上；
    - 把同一条用户消息用新的 `client_message_id` 再发一次，新回答接在后面，不替换旧回答，历史保持线性；
    - 原消息带了附件时不可用，提示「附件已随原消息发送，请重新附加后再发」。附件只能绑定一次，后端不改；
  - ⋯ 菜单：存为报告（复用现有的 SaveReportDialog）、复制为纯文本。
- 不做赞 / 踩：目前没有地方使用这些数据，以后要加很容易。

**输入框**
- Enter 发送，Shift+Enter 换行。输入法候选期间（`isComposing`）按 Enter 不发送。
- 圆角大框；「＋」打开菜单：文件、图片；移动端还有拍照。
- 模型选择放在框内右侧。
- 生成中，发送键变成停止键。
- 空对话时，输入框居中，上面一行「今天要排查什么？」，下面是现有的入门建议。

**滚动**
- 跟随最新内容自动吸底。
- 用户向上翻看时停止吸底，并显示「↓ 回到底部」按钮。

**代码块**
- 加「复制」按钮。
- 不做语法高亮（避免新增依赖；运维输出里大多是命令和 YAML，等宽字体已经够读）。

**移动端（< 768 px）**
- 对话列表是抽屉，从左上角按钮打开。
- 输入框贴底，并留出 safe-area。
- 输入框里的附件横向滚动。
- 没有拖拽：用「＋」选文件 / 相册 / 拍照，粘贴照常可用。
- 图表按宽度自适应；流程图可以横向滚动，点开后可缩放。
- 大图预览框支持左右滑动切换。

**主题**：深色模式沿用现有的颜色变量。

## 不做

- 复制 OpenAI 的品牌资产。
- 对话分支、编辑历史消息后重发。
- 语音输入。
- Canvas 式的协同编辑。
- 显示模型的思考文本。
- 赞 / 踩。
- 语法高亮。
- 报告与通知里的图表渲染。
- IM 渠道的富消息。
- 新的 agent 工具：图表靠输出格式，不靠工具。

## 反目标（技术上做对了也算失败）

- **行高跳动**：富渲染让虚拟列表的行高跳动、没法吸底，或者让长对话明显变慢。
- **执行模型输出**：模型输出里的任何内容被当作代码执行。mermaid 用 strict 模式，图表 JSON 只当数据。
- **泄露凭证**：工作过程的摘要或结果预览里漏出凭证。
- **移动端不可用**：移动端只是缩小了的桌面版，按钮点不到，输入框被键盘挡住。

## 验收

1. **各类内容的渲染**（浏览器 E2E，真实模型）：
   - 问统计类问题，得到柱状图、饼图或趋势图；
   - 问调用链或流程，得到渲染出来的流程图，回答里没有 ASCII 图；
   - markdown 表格正常显示；
   - 消息和输入框里的图片缩略图可以点开大图，图表和流程图可以放大。
2. **工作过程**：
   - 运行中能看到逐步出现的步骤，有耗时和状态；
   - 过程话在块里，正文开头不再是「我先查一下……」；
   - 完成后收起；
   - 刷新页面后点开，内容一致；
   - 脱敏：上面列的四种凭证写法，在摘要和预览里都被盖掉（单元测试 + 一次真实命令）。
   - 同一个问题从 IM 或定时任务进来时，回答里没有 `chart` / `mermaid` 块。
3. **附件**：
   - 拖进对话区任意位置都能放下；
   - 附件出现在输入框里，有缩略图、进度、类型色块和失败原因；
   - 上传完成前不能发送。
4. **下一步建议**：显示在回答末尾，点一下就发送。
5. **移动端**（Playwright 设备模拟，iPhone 尺寸）：
   - 抽屉、输入框贴底、附件横向滚动、「＋」菜单、图表自适应、大图预览滑动切换都正常；
   - 主要按钮都能点到。
6. **输入**：Enter 发送、Shift+Enter 换行，中文输入法候选期间按 Enter 不发送；用户上翻时出现「↓ 回到底部」。
7. **性能**：200 条消息的长对话滚动不卡、不跳动；没有流程图的对话不下载 mermaid。
8. **测试与构建**：vitest、`tsc`、在 `/tmp` 干净目录里 `npm ci && npm run build` 全部通过；后端全量测试没有新增失败（已知的 DNS 误报除外）。
9. **文档**：`docs/MVP-2.7.1-RELEASE.md` 增加这一项；README 中英文同步更新，CLAUDE.md 和 WORKFLOW 同步更新。
