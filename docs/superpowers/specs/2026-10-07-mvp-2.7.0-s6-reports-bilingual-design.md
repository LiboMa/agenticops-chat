## 1. 背景与决定

- **现状**（2026-10-07 核实）：
  - 报告是纯 markdown：没有版本、哈希、语言、归属。
  - 没有渲染和翻译，没有导出接口，整个应用没有打印样式。
  - 发布点了就发：没有确认、不显示目的地、不能幂等。
  - 列表和详情页的文案全是写死的英文。
  - 从私有 chat 保存的报告所有人可见（S1 遗留：「报告本身没有归属，S6 再议」）。
- **已有可复用的**：
  - `notify/report_formatter.format_report`：html / pdf（weasyprint，可选）/ docx（python-docx，可选）；
  - SNS / SES 发布路径（`notifier.SNSReportNotifier` / `SESNotifier`）；
  - `storage/backend`；
  - 便宜模型调用模式：`signal_gate._call_bedrock`、RCA 评审、安全建议都是 temperature 0，失败即 fail-closed；
  - `services/chat_access` 的可见性模式。
- **主人决定（2026-10-07）**：
  1. **只做报告**：渲染接口按契约通用地建，只开放 `entity_type=report`；事件、方案、变更的正文保持原语言。
  2. **新报告自动准备，旧报告用按钮**：每份新保存的报告在后台准备另一种语言；旧报告显示「未准备」和「准备翻译」按钮；切换语言从不调用模型。
  3. **私有 chat 的报告保持私有**：只有创建者和管理员可见、可导出、可发布；其他报告与今天一样全工作区可见。
  4. **当前 / 双语切换**（按原型）：导出、打印、发布都按当前显示的方式（zh / en / zh-en）。

## 2. 设计

### ① 版本、归属、渲染（后端）

- **`reports` 新增列**（走 2.7.0 增量迁移）：
  - `content_version`：从 1 开始；今天报告正文不会被修改，所以一直是 1。
  - `content_hash`：正文的 sha256。旧行在迁移时补算。
  - `source_language`：`zh` 或 `en`，由纯函数按中日韩字符占比判定。
  - `owner_user_id`、`visibility`（`private` / `workspace`）：旧行为 `workspace`。
- **可见性**：
  - 从私有 chat 保存的报告（`POST /api/reports/from-session` 且会话为 private）为 `private`，归创建者。
  - 新模块 `services/report_access`（照 `chat_access`）提供 `visible_filter`、`get_visible_report`（看不见即 404，与不存在一致）和 `new_report_owner`。
  - 报告的所有路由都先过它：列表、详情、渲染、翻译、导出、发布、分享。
- **新表 `content_renderings`**：
  - 唯一键 `(entity_type, entity_id, source_version, language)`。
  - 其他列：`source_hash`、`status`（`ready` / `pending` / `failed`）、`body_markdown`、`protected_value_hash`、`error_code`、`generated_at`。
  - 源语言的渲染就是源本身：读取时直接给 `ready`，不建行、不调模型。
- **`GET /api/content/report/{id}/rendering?version&language`**：
  - 普通 `def`，只读，从不调用模型。
  - 返回契约的 `ContentRendering`：`status` ∈ `ready` / `pending` / `missing` / `failed` / `stale`。
  - 行的 `source_hash` 与报告当前的 `content_hash` 不同即为 `stale`。
  - `version` 不是当前版本返回 404。

### ② 翻译（后端）

- **保护值**（纯函数 `services/content_protect.py`）：
  - 送进模型前，把所有不能改的值替换成编号占位符 `⟦P12⟧`：围栏代码块、行内代码、`I#` / `R#` / `C#` / `E-…` 等证据与对象引用、ARN 与资源 id、IP、URL、所有数字。
  - 模型看不到这些值，也就改不了。
  - `protected_value_hash` = 按出现顺序排列的保护值的 sha256。
- **校验（fail-closed）**：
  - 译文里每个占位符必须恰好出现一次，不能多、不能少、不能新增。
  - 还原后重新抽取保护值，哈希必须与源一致。
  - 任一不满足，渲染存为 `failed`，`error_code=protected_values_changed`，不展示任何部分译文。
  - 模型调用失败存为 `failed`，`error_code=model_failed`。
- **模型**：便宜模型（`report_translation_model_id`，空 = `bedrock_model_id_cheap`，配置在 `settings.yaml`），temperature 0，按 markdown 结构整篇翻译。提示词要求：保留所有占位符和 markdown 结构，只翻译自然语言。
- **执行**：
  - 在这一个进程（S1）的后台线程里跑：先把 `pending` 行落库，再翻译。
  - 每个 `(report, version, language)` 一把进程内锁。
  - 已有 `ready` 且 `source_hash` 相同时直接复用，不会翻译两次。
  - 启动时把残留的 `pending` 置为 `failed`（`error_code=interrupted`），可以重试。
- **何时触发**：
  - 任何新保存的报告：agent 的 `save_report`、`from-session`、`generate`、`report/generator`，都把另一种语言加入队列。
  - `POST /api/content/report/{id}/translations`（`TranslationRequest {source_version, languages}`）返回 202 加各语言的 `ContentRendering`：已就绪的直接返回，没有的入队，失败的重新入队。这就是「准备翻译」和「重试」按钮。

### ③ 导出、打印、发布

- **`GET /api/reports/{id}/export?version&language=zh|en|zh-en&format=html|pdf|docx`**：
  - 普通 `def`，`Content-Disposition: attachment; filename=AgenticOps_R{id}_v{n}_{lang}.{ext}`，`ETag` = 内容哈希。
  - `zh-en` 是两份已就绪的渲染先后排列，中间分页。
  - 请求的语言没有就绪返回 409 `rendering_not_ready`。
  - 不可用的格式返回 422 `format_unavailable`：html 始终可用，pdf / docx 取决于服务器是否装了对应的库。
  - 导出从不发布，也不写任何发布记录。
  - HTML 用独立模板：`lang` 属性按语言，带打印样式。
- **打印**：报告详情页加打印样式（A4、16mm 边距；只打印纸面；zh 与 en 之间分页；标题不在页尾；检查行不跨页）。按钮调用 `window.print()`。
- **发布** `POST /api/reports/{id}/publish`：
  - 请求体在 `{channel_name, formats}` 基础上新增 `version`、`language`；请求头 `Idempotency-Key` 必填（16–200 字符，否则 422）。
  - 只发送这个版本、这个语言的已就绪渲染；未就绪返回 409。
  - 同一个 key 再次发布返回第一次的结果，不会再发送。结果按 key 存在报告的 `report_metadata.publications` 里。
  - 渠道仍然只有 sns-report / ses。
- **bootstrap**：`features.content_rendering = true`，`features.report_export = true`，另加 `report_export_formats`（实际可用的格式列表）。

### ④ 报告页面（蓝白、双语）

- **列表**：
  - 每行显示版本（`v1`）、类型、语言状态（zh / en 各显示「就绪 / 准备中 / 失败 / 未准备」）、私有标记。
  - 所有文案走 locale；按天分组和搜索保留。
- **详情**：
  - 顶部：编号 / 版本、类型、生成时间、源语言、关联对象（`report_metadata` 里有 session / issue 就显示，不按标题猜）。
  - **当前 / 双语**切换：当前 = 界面语言的一份纸面；双语 = 中英并排（≤1350px 时上下排列）。
  - 工具栏：导出（主按钮，弹出语言 / 格式选择，不可用的格式置灰）、打印、分享、发布。
  - 页脚说明：「报告绑定它的版本和证据；切换语言不改变任何事实或状态。」
  - 另一种语言不可用时，纸面位置显示：
    - 「准备中…」（轮询直到就绪）；
    - 「翻译失败 · 重试」，附失败原因的本地化说明；
    - 「未准备 · 准备翻译」。
    - 并始终给出「以源语言（xx）阅读」。永不静默混排语言。
- **发布确认框**：
  - 先显示真实目的地：SNS topic ARN，或 SES 收件人列表。
  - 显示报告编号 / 版本 / 语言、格式选择，一个确认按钮。
  - 每次打开生成一个新的 `Idempotency-Key`；同一个框里重复点击用同一个 key。
- 原有的 Share 对话框保留。分享内容带版本和语言。

### ⑤ 非目标

- 事件、方案、变更的中英渲染；
- 编辑报告、生成新版本；
- sns-report / ses 之外的发布渠道；
- CLI 报告视图；
- 翻译质量评估（只保证保护值不变）。

## 3. 六个可达面

| 面 | 做 / 非目标 |
|---|---|
| CLI | 非目标：报告没有 CLI 视图。`aiops report` 生成的报告照样自动入队翻译 |
| Web API | 做：§2 ①②③（列 / 表、可见性、渲染读取、翻译入队、导出、带版本 / 语言 / 幂等键的发布、bootstrap 开关） |
| Web UI | 做：§2 ④（列表与详情双语化、当前 / 双语切换、准备 / 失败 / 未准备状态、导出与打印、发布确认框） |
| Agent tool | 做（间接）：`save_report` 保存后自动入队翻译；不新增工具 |
| Schedule | 做（间接）：定时报告经同一保存路径自动入队翻译 |
| Notification | 做：发布（SNS / SES）只发送选定的版本和语言，并且幂等 |

## 4. 已知缺口（预先写明）

- 只保证保护值不变，不评估译文质量；数字和标识符之外的事实（例如「增加 / 减少」）仍依赖模型。
- 报告正文不可编辑，所以 `content_version` 一直是 1；版本机制已就位，有编辑路径时再用。
- pdf / docx 依赖服务器上的可选库；没装时只有 html 和浏览器打印。
- 发布结果记录在报告的元数据里，不是单独的发布表。
- 私有报告只覆盖从私有 chat 保存的那一种；其他来源都是全工作区可见。

## 5. 交给主人的验收清单

1. **自动翻译**：新保存一份报告（例如 Chat 的「保存为报告」），几十秒内另一种语言变为「就绪」；切换界面语言不触发任何模型调用。
2. **旧报告**：显示「未准备 · 准备翻译」，点击后变为「准备中」，再变为「就绪」。
3. **保护值**：译文里的命令、`I#` 引用、ARN、数字与原文一致。故意让校验失败时（单元测试覆盖）显示「翻译失败 · 重试」。
4. **双语切换**：当前 / 双语；双语时中英并排；窄屏上下排列。
5. **导出**：导出 html（zh / en / zh-en），文件名带编号 / 版本 / 语言；未就绪的语言不能选；pdf / docx 按服务器能力可选或置灰。
6. **打印**：打印预览只有纸面，双语时中英分页。
7. **发布确认**：发布框显示真实目的地（topic ARN / 收件人）、版本和语言；确认后才发送；重复点击只发一次。
8. **私有报告**：alice 从自己的私有 chat 保存报告，bob 看不到（列表没有、直接访问 404），admin 能看到。
9. **中英文**：列表和详情的全部文案随界面语言切换。
