# MVP-2.7.0 S4 — Cases 双栏 + 账户范围 + 补充说明 + Resources 表格：设计

> 主人 10-07 批准。实施计划：[2026-10-07-mvp-2.7.0-s4-cases-resources.md](../plans/2026-10-07-mvp-2.7.0-s4-cases-resources.md)

## A1. Context

- 路线图 S4 =「Cases 与 Resources」：
  - Cases 队列 + 阅读区双栏（保留 2.6.1 的阶段卡）；
  - HealthIssue hooks 替换 Anomaly；
  - URL 承载筛选与选中项；
  - 补充说明接口；
  - 顶栏账户范围；
  - Resources 表格。
- 现状问题（已核实）：
  - 事件列表走旧的 Anomaly 形状，丢了出现次数、锚点等字段，所以 ×N 永远是 1。
  - 只看最新 50 条，状态、严重度、搜索都在浏览器端对这 50 条筛选；筛选不在 URL 里。
  - 没有补充说明；没有任何页面能带着事件打开 Chat。
  - 账户筛选每页各一套。
  - 资源列表行不是真链接，表头写死英文，没有健康和观测时间；翻页没有排序，会重复或漏行。
  - 全景图的事件对话框把 HealthIssue 当成 Anomaly 读，指标字段全空（已经坏了）。
- 主人 10-06 / 10-07 的决定：
  1. **顶栏一个全局账户范围**，替换各页的账户筛选。它统一作用于事件队列、方案与变更两个列表、资源表格和「需要你处理」，按用户存在本浏览器。
  2. **补充说明只追加**，进事件的处理记录，带作者和时间，不能改也不能删；写入需要 write 权限。
  3. **S4 里 Agent 不读补充说明**（S5 随 Chat 上下文一起做）；「询问 Agent」只负责带着事件打开 Chat。
  4. **队列保留现有筛选**（运维 / 安全 / 全部、状态、严重度、搜索），全部改为服务端筛选并写进 URL；一次最多 200 条，超过时提示。
  5. （早先的决定）事件详情保留 2.6.1 的阶段卡，不做标签页；阅读区直接放这些内容。
- 工作环境：
  - 主检出，MVP-2.7.0 分支。
  - 另一会话（A1 轨道）以后也会改 `IssueDetail.tsx`、`ResourceDetail.tsx`、`authz.py`、`rbac.yaml`：改这些文件前先 `git status` 并通知对方，当次提交。
  - 测试一律用 `.superpowers/aiops-pytest.sh`。

## A2. 设计要点

### ① 事件读接口（`GET /api/health-issues`）

- 改为普通 `def`。
- 新参数：
  - `scope=ops|security|all`：默认 `all`，兼容其他调用方。逻辑从 `api_list_anomalies` 原样抽到 `web/helpers.issue_scope_filter`，两个接口共用。
  - `status`、`severity`：都接受逗号列表，未知值返回 422。
  - `q`：标题、资源 id；`I#12` 或 `12` 匹配事件编号；LIKE 转义复用 `_like`。
  - `sort=newest|oldest|severity`：服务端排序。
  - `limit` 不超过 500。
- 返回形状不变（`HealthIssueResponse` 已含 `account_name`、`occurrence_count`、锚点字段）。
- 前端用 `limit=201` 判断是否超过 200 条。

### ② 补充说明

- 新权限 `issue.note: [write]`。四处一次加齐：`authz.PERMISSIONS`、`DEFAULT_POLICY`、`config/rbac.yaml`、`infra/eks-chaos-lab/agenticops/rbac.yaml`。权限表与 yaml 必须同一提交，否则校验失败会让整个文件退回内置默认。
- 新增 `services/issue_notes.add_note(session, issue, content, actor)`：在请求自己的事务里直接插入一行 `PipelineEvent`，**不经 `log_event`**（它会吞掉错误）。
  - 字段：`event_type="note_added"`，`stage="note"`，`status="recorded"`，`detail={"content"}`，`actor=actor.key`，`trace_id=issue.trace_id`。
- `POST /api/health-issues/{id}/notes`：
  - 请求体 `{content}`：去掉首尾空白后 1–8000 字；`extra="forbid"`；拒绝 NUL 和除 `\n`、`\t` 外的控制字符。
  - 权限：`authz.check(actor, "issue.note", issue)`，拒绝返回 403。影子模式下照常是「审计但放行」，与全平台一致，并写进文档。
  - 返回 201 `IssueNote {event_id, health_issue_id, content, actor, created_at}`；事件不存在返回 404。
- `GET /api/health-issues/{id}` 改为 `def`，并带 `available_actions: [{action: "note", allowed, reason_code, effect: "update"}]`，用 `ui_actions.route_allows` 计算。
- 前端：处理记录里每条说明单独一行，**只按纯文本渲染**，永不合并、永不隐藏；输入框在 note 动作被允许时出现。

### ③ 资源接口

- `GET /api/resources` 改为普通 `def`，按 `(resource_type, id)` 排序，翻页稳定。
- 每行带 `open_issues` 和 `health`，复用 `graph/query_service.health_overlay`：
  - 与全景图同一个四值定义：`unknown` / `notice` / `warning` / `critical`；
  - 只算未结状态、同账户的事件；
  - 没有事件 = `unknown`，**不等于健康**。
- `scanned_at`、`absent_since` 已在响应里。

### ④ 前端迁移到 HealthIssue

- 新 `hooks/useHealthIssues`，查询键仍以 `["anomalies", …]` 开头，现有 6 处失效调用不用改。
- `issueRow(HealthIssue, search)` 改用 `issueFacts` 读 `metric_data`。
- 迁移 Dashboard、全景图事件对话框（顺带修好指标字段为空）、GalaxyNodePanel、ResourceDetail、`useResourceIssues`。
- 删除 `useAnomalies` 和 `Anomaly` 类型。

### ⑤ 账户范围

- 纯函数 `lib/accountScope.ts`：
  - 按用户分键（`userKey`）；
  - 存的 id 不在账户列表里时回到「全部账户」；
  - `scopeMode(pathname, wide)` 返回 `active` / `locked` / `notApplied`：
    - `active`：生效的列表页，以及宽屏下的事件双栏页；
    - `locked`：详情页，以及窄屏下的事件全屏详情；
    - `notApplied`：总览、安全、全景图等不受它约束的页面，显示为灰，并提示「本页不按账户筛选」。
  - `adoptAccountParam(search)`：旧链接里的 `?account=`（修复方案）或 `?account_id=`（变更）只在进入时读一次，设为全局范围，然后从 URL 里去掉，并提示「已按链接设置账户范围」。
- `AccountScopeProvider` 放在 AppShell；顶栏下拉放在「需要你处理」和搜索之间。
- 消费方：
  - 事件队列；
  - 修复方案标签、变更标签：去掉它们自己的账户下拉；
  - 资源表格：去掉账户下拉；
  - `useAttention`：传 `account_id`，查询键带上账户；弹框里写明「已按 X 筛选」。
- 没有账户的事件和变更（`account_id` 为空）在选了某个账户后不显示，这一点写进已知缺口。

### ⑥ Cases 双栏

- 路由：`issues` 改为嵌套路由，渲染 `CasesPage`（队列）加 `<Outlet/>`：
  - index：占位「请选择列表中的记录」；
  - `:id`：阅读区。
  - 队列在切换选中项时不会重新挂载。
- 宽度：屏幕 ≥1280px 时两栏。队列 300px（≤1350px 时 280px，都在设计规定的 280–320px 内）；阅读区最大 960px。
- 屏幕 <1280px：
  - `/app/issues` 只显示列表；`/app/issues/:id` 显示全屏详情。
  - 返回：如果是从队列进入的（`location.state.fromQueue`），用 `navigate(-1)`；否则链接到带原查询串的列表。
  - 列表滚动位置在点行时存进 sessionStorage，按查询串分键；回到列表后恢复，焦点回到原来那一行。
  - 打开详情时滚到顶部（有 hash 时除外）。
- 队列：
  - 结构是 `<nav>` 里一个 `<ul>`，每行是真的 `<Link>`，选中行带 `aria-current`。方向键只移动焦点，回车或点击才选中，选中时焦点不跳进阅读区。
  - 每行显示：编号、严重度、标题、「资源 · 状态」、等谁。
  - 行内快捷操作去掉，操作都在阅读区。
  - 每个选项旁的计数去掉：只对已加载的那几条计数，本来就不准。
- 筛选写在 URL：`scope`、`status`（全部 / 进行中 / 已解决 / 已忽略 → 对应的状态列表）、`severity`、`q`、`sort`。选中某条时保留查询串。
- 阅读区：
  - `IssueDetail` 新增 `embedded` 模式：不显示返回链接（`StatusLine` 的 `backTo` 改为可选），单栏布局，信息栏放到卡片下方。
  - 以 `key={issueId}` 挂载，切换事件时重置本地状态，并把阅读区滚动回顶部。

### ⑦ 询问 Agent

- `lib/contextRef.contextRefFromQuery`。
- Chat：
  - 读取 `?ref=I12`；有 ref 时**不恢复上次会话**，打开一个新对话，同时打开该事件的上下文面板。
  - 不自动发送。在欢迎页点上下文面板的「让 Agent 核对」时，用 `sendFirstMessage` 发出。
- IssueDetail 的 ⋯ 菜单加「询问 Agent」。

### ⑧ Resources 表格

- 纯函数 `lib/resourceTable.ts`：
  - URL 筛选：`type`、`region`、`q`、`absent`、`page`、`size`；
  - 健康和生命周期的文案键；
  - 行链接只用整数主键。
- 列：名称（下面一行是原生 id）、类型、账户、区域、生命周期（存在 / 已消失）、健康（未结事件数 + 四值状态；没有事件显示「未知」，不说「健康」）、最近观测（`scanned_at`）。
- 每行是真链接，可以中键在新标签打开；全部文案走 locale。
- 去掉表头的点击排序：它只能排当前这一页，会误导。

### ⑩ 已知缺口（写进 RELEASE）

- 补充说明在影子模式下「审计但放行」。
- 没有账户的事件和变更，在选了某个账户后看不到。
- 总览、安全、全景图、侧栏红点不按账户范围筛选（页面上会提示）。
- `/api/resources/{id}/issues` 仍按资源 id 字符串匹配，和健康列按锚点的口径不同。
- `HealthIssue` 的 `detected_at` 和 `account_id` 没有索引，`q` 用 ILIKE：在当前规模下可以接受。

## A3. 交给主人的验收清单

1. **双栏**：
   - 1440px 下打开 `/app/issues`：左边队列、右边「请选择记录」。
   - 点一条，右边出现阶段卡，URL 变为 `/app/issues/N?…`，筛选保持。
   - 切换事件时，右边内容和滚动位置都重置。
2. **筛选**：运维 / 安全 / 全部、状态、严重度、搜索、排序都写进 URL，刷新后保持；搜索 `I#3` 能直接找到；超过 200 条时有提示。
3. **窄屏**（1000px / 390px）：
   - 列表 → 全屏详情 → 返回，回到原来的筛选和滚动位置，焦点在原来那一行。
   - 浏览器后退同样有效。
4. **账户范围**：
   - 顶栏选一个账户后，事件、修复方案、变更、资源、待办都只剩这个账户；待办弹框里写明正在按哪个账户筛选。
   - 在详情页它变灰；在总览页它变灰并提示不筛选。
   - 打开旧链接 `/app/plans?account=1`：范围被设为该账户，URL 里的参数被去掉，并有提示。
5. **补充说明**：
   - 写一条，出现在处理记录里，带作者和时间。
   - `<script>` 原样显示为文本；空内容不能保存。
   - 用 alice 和 admin 各写一条，作者不同。
6. **询问 Agent**：事件 ⋯ 菜单 →「询问 Agent」→ 打开一个新对话，上下文面板显示这个事件，不会自动发送。
7. **Resources**：
   - 表格各列齐全；没有事件时健康显示「未知」。
   - 每行可以中键在新标签打开；筛选写进 URL；翻页不重复。
8. **全景图**：点资源 → 事件对话框，指标字段有值（以前是空的）。
9. **中英文**：所有新文案都随语言切换。
