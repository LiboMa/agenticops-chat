# ③ P0.5 Skills Loader/UX Hardening — Design Doc

- **日期**: 2026-05-31
- **周期**: ③ 子项 P0.5（cycle③ 主线之外的"借鉴增强"补丁）
- **基线分支**: `cycle3-skills-autonomy`（基于 P1 Curator commit `50ce198`）
- **目标分支**: `cycle3-p0.5-loader-hardening`（单仓库分支切换，无 worktree）
- **范围**: 把 Strands SDK `AgentSkills` 插件源码里的 5 项稳健性/UX 增强借鉴到 AgenticOps 自建 skills 加载层
- **不含**: 改变 cycle③ 自治化主线（Curator/skill_manage/provenance）；不动 P1 Curator 已 commit 的代码

---

## 1. 背景与动机

### 1.1 触发事件
读 Strands SDK 源码 `strands-py/src/strands/vended_plugins/skills/{agent_skills.py, skill.py}`（共 845 行），与 AgenticOps `src/agenticops/skills/loader.py`（388 行）+ `tools.py` 逐项对比后，发现 5 处可低成本借鉴的稳健性/UX 改进。其中 1 处是真 bug（A1 XML escape），其它 4 处是健壮性/可读性增强。

### 1.2 为什么不直接用 Strands `AgentSkills`
完整对比已记录在会话；要点：
- AgenticOps 独有 `tools:` 字段动态注入 @tool（Strands 没有）
- AgenticOps 独有 `skills/draft/` published-shadows-draft 工作流（cycle③ 核心）
- AgenticOps 独有 cycle③ provenance（`created_by/status/skill_version`）
- AgenticOps 独有 `security.py` 安全分级 + 路径穿越防护
- AgenticOps 的 mtime 自动 reload 比 Strands 的显式 `set_available_skills(...)` 更省心
- Strands `allowed-tools` 标"informational only"，没强制；fork context 没实现

**结论**：保留自建，按规范靠拢；只挑增量价值高、与现架构无冲突的 5 项做局部补丁。

## 2. 借鉴清单（已与用户确认）

| # | 项 | 来源（Strands） | 现状（AgenticOps） | 性质 |
|---|---|---|---|---|
| **A1** | XML escape `<available_skills>` 描述/名字 | `agent_skills.py:294` (`xml.sax.saxutils.escape`) | `loader.py:253` 直接拼字符串 | **真 bug** — 含 `<` `>` `&` 的描述会破坏 system prompt |
| **A2** | YAML colon-fallback 解析 | `skill.py:89-111` (`_fix_yaml_colons`) | `loader.py:104` 直接 fail-soft | 健壮性 — 用户写 `description: Use when: foo` 不再静默丢失 |
| **A3** | 严格 name 格式校验 + 父目录名匹配 | `skill.py:23, 114-163` (`_validate_skill_name`) | `loader.py:149` 无校验，仅 fallback 到目录名 | 健壮性 — 防 frontmatter 写错 name 导致默默使用错误标识 |
| **B1** | `activate_skill` 自动列 `scripts/`+`references/`+`assets/` | `agent_skills.py:247-275` (`_list_skill_resources`) | `tools.py:97-109` 仅遍历 `references/*.md` | UX — agent 一次激活看到全部资源，不用再多调一次 |
| **B2** | XML 索引描述截断 80 → 200 + 去掉首句切分 | Strands 默认不截断 | `loader.py:251` `.split(".")[0][:80]` | UX — 提高索引召回率，~1.7 KB token 增量可接受 |

不做（YAGNI）：
- **B3** `allowed-tools` 解析 — 只解析不强制等于"虚假沙箱"，留 cycle④
- **C1** HTTPS URL 加载 skill — 与安全优先原则冲突
- **C2** lowercase `skill.md` fallback — 价值低
- **C3** per-invocation 注入 — 破坏 Bedrock prompt cache
- **C4** `activated_skills` 持久化 — 子 agent 短生命周期不需要

## 4. 架构决策

| # | 决策 | 理由 |
|---|------|------|
| D1 | 改动**纯加法**，公共 API 不变 | 不影响 cycle③ 主线代码；新增 `list_skill_resources()` 是新公开符号，不替换旧的 |
| D2 | 校验**lenient（log WARNING + skip）**，**不 raise** | 与现有 `_scan_directory` 的鲁棒性一致；Strands 也是默认 lenient（`strict=False`） |
| D3 | A1 XML escape 用 `xml.sax.saxutils.escape` 而非自写 | 标准库，零依赖，Strands 同选择 |
| D4 | A2 colon-fallback 仅在 yaml.safe_load 失败时触发 | 不影响合法 YAML 的解析路径；fallback 仍失败则 fail-soft 返回 `({}, content)`（保留现有行为） |
| D5 | A3 校验在 `_scan_directory` 内做，**不**在 `parse_frontmatter` 做 | parse 关注解析；scan 关注合法性。职责分离 |
| D6 | B1 通过新 helper `list_skill_resources()` 暴露 | tools.py 调用变干净；helper 可被未来其它消费者复用（如 WebUI） |
| D7 | B2 截断保留 ASCII 字符截断逻辑（不按 token 计算） | 简单；按字符截断的偏差对 200 字符文本仅 ±10 token，可接受 |
| D8 | **不**改 `_MAX_DESC_XML` 为 settings 配置项 | 200 是 sweet spot，YAGNI；将来真要调，改常量比改 settings schema 简单 |
| D9 | 隔离方案：**单仓库新建分支 + checkout** | 用户偏好——避免 worktree 共享 venv 时 pytest 抢锁卡死的历史问题。前置条件：当前 worktree 必须 clean（无未提交改动），否则中止。 |

## 5. 数据模型 / 接口变更

### 5.1 新增公开符号（loader.py）
```python
# 公共
def list_skill_resources(skill_name: str) -> list[str]: ...

# 私有但测试可见
def _validate_skill_name(name: str, skill_dir: Path) -> bool: ...
def _fix_yaml_colons(yaml_str: str) -> str: ...

# 模块常量
_SKILL_NAME_RE: re.Pattern        # ^[a-z0-9]([a-z0-9-]*[a-z0-9])?$
_MAX_SKILL_NAME_LEN: int = 64
_RESOURCE_DIRS: tuple = ("scripts", "references", "assets")
_MAX_RESOURCE_FILES: int = 20
_MAX_DESC_XML: int = 200
```

### 5.2 修改的现有函数（loader.py）
- `parse_frontmatter()` — 增加 colon-fallback 重试 + 非-dict 防御
- `_scan_directory()` — 描述检查后增加 `_validate_skill_name()` 调用
- `build_available_skills_xml()` — 替换截断逻辑 + XML escape

### 5.3 修改的现有函数（tools.py）
- `activate_skill()` — 用 `list_skill_resources()` 替换内联 `references/` 遍历
- 顶部 import 增加 `list_skill_resources`

### 5.4 现有 SKILL.md frontmatter 不变
不增字段，不删字段。A3 严格校验仅是验证 `name` 字段合法性。

## 6. 关键修复说明

### 6.1 A1 — 真 bug 还原
当前代码：
```python
lines.append(f'  <skill name="{s.name}">{tag}{short_desc}</skill>')
```
若某 skill 的 description 包含 `Use when X & Y < Z`，最终注入 system prompt 的 XML 会出现：
```xml
<skill name="...">Use when X & Y < Z</skill>
```
对 LLM 不必然破坏，但是 ill-formed XML，会让模型误解析或 cache 命中率下降。Strands 用 `xml.sax.saxutils.escape` 已防护——AgenticOps 应同步。

### 6.2 A2 — 用户认知对齐
agentskills.io spec 推荐处理这种"colons in unquoted values"——Strands 实现了，AgenticOps 没有。`description: Use when: foo` 是 SRE 写 skill 时极其常见的格式（"Use when: 描述"），现在直接静默吞掉。修复后用户得到他期望的解析结果。

### 6.3 A3 — 防 silent miscategorization
当 frontmatter 写 `name: redis-admin-v2` 但目录是 `redis-admin`，现状会用 frontmatter 的名字，但磁盘还是旧目录——下次 `read_skill_reference` 拿不到 references；XML 索引看到 `redis-admin-v2` 但 `activate_skill("redis-admin-v2")` 内部走 `_get_skill_by_name("redis-admin-v2")` 又能找到——表面正常但语义混乱。强制等于目录名 = 唯一性源。

### 6.4 B1 — 减少 LLM 决策步数
现状：agent 调 `activate_skill` → 看到只有 references/ 列表 → 想 read scripts/ 还要再 `read_skill_reference("scripts/x.sh")` 试探。改进：一次激活看到所有资源，节省至少 1 次 round-trip。

### 6.5 B2 — Token 经济性核算
14 个 published skills × 120 字符增量 ≈ 1.7 KB ≈ ~425 tokens。cycle③ spec §5 已设阈值 2000 tokens，本改动远低于。

## 7. 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| A3 严格校验误伤现有 14 个生产 skills | 部分 skill 不被加载，agent 失去能力 | Task 3 Step 5 显式跑 `discover_skills()` 校验全部 14 个加载成功；任一失败必须 fix skill 的 frontmatter，**不放松规则** |
| A2 colon-fallback 误伤合法嵌套 YAML | 把合法的 `key: 子映射` 错误地引号包裹 | regex `^(\s*\w[\w-]*):\s+(.+)$` 仅匹配"key + 空格 + 至少 1 字符 value"的标量行；纯 `key:` 的嵌套起点不匹配。测试 `test_truly_broken_yaml_still_returns_empty` 防御 |
| 与 P1 Curator 工作冲突 | 双方改 loader.py 同片段 | P1 已 commit `50ce198`；P0.5 基于该 commit 切新分支；任务期间不再切回 cycle3-skills-autonomy 修代码 |
| 启动前有未提交改动会被切分支带走 | 改动跟着进新分支，污染 P0.5 commit | T0 启动前 `git status` 必须 clean；不 clean 就 stop 让用户先处置 |
| XML escape 改变现有测试断言文本 | 回归测试断言失败 | Task 1 Step 5 + 后续 Step 4/5/6 在每 task 后跑全套 `test_skills_loader_coverage.py` |
| description 截断从 80 → 200 注入 token 超预算 | prompt 变长 | §6.5 已核算，远低于阈值 |
