# Strands SDK 1.26→1.45 升级 + 3 项增强 — 设计文档

**日期**: 2026-07-04
**分支**: MVP-2.0.1（逐项 commit，当前分支）
**状态**: 待审阅

---

## 1. 目标与范围

将 AgenticOps 的 `strands-agents` 从 **1.26.0 升级到 1.45.0**，并落地 3 项功能上有真实收益的增强。目标：**安全、增量、可回滚**，每步有 E2E 验证。

### 最终范围（7 项 → 4 项做，3 项缓）

| # | 项 | 裁定 | 理由 |
|---|---|---|---|
| ① | 升级 1.26 → 1.45 | ✅ 做 | 一切入口；唯一 breaking 是 MistralAI 2.x（本项目只用 Bedrock，不受影响） |
| ② | `context_manager="auto"` | ✅ 做 | 一行；省 token + 治大输出；与现有 conversation_manager 共存 |
| ③ | ContextOffloader | ✅ 做 | 直解 executor "tool_result too large" 痛点；`auto` 已内含 |
| ④ | HumanInTheLoop | ✅ 做 | executor 并行加一层 SDK 级安全网，不拆旧逻辑 |
| ⑤ | structured_output | ❌ 缓 | RCA/FixPlan 现用 save 工具落库，工作正常、无解析痛点 → 为改而改 |
| ⑥ | OTLP 可观测性 | ❌ 缓 | 无 tracing 后端，当前无实际用途 → 违反"不加没用功能" |
| ⑦ | Evals 回归测试 | ❌ 缓 | 已有 164 个测试文件强基线；新增 Evals = 新依赖+新体系，当前非必需 |

⑤⑥⑦ 降级为"未来待办"，等真实触发点出现再做（RCA 真解析失败 → structured_output；接了 Jaeger/X-Ray → OTLP；发现 agent 路由退化 → Evals）。

### 关键洞见：② 和 ③ 合并

官方文档确认：`context_manager="auto"` 内部组合 `SummarizingConversationManager`(summary_ratio=0.3, threshold=0.85) + `ContextOffloader`(max_result_tokens=1500, preview=750)。**当同时传 `conversation_manager` 时，用户的 conversation_manager 保留（不被替换），SDK 只额外加 ContextOffloader**。

→ 因此 ②③ 是**一个动作**：给每个 agent 加 `context_manager="auto"`，现有 per-agent 窗口策略（rca/sre=Null 全上下文，其余=SlidingWindow）全部保留，只多得 ContextOffloader。

## 3. 架构与改动点

### 现状（不变的部分）
- 7 agent，agents-as-tools（main 路由 + 6 专家 @tool）
- 每个 agent 构造：`system_prompt / model / conversation_manager / callback_handler / tools`
- 聊天路由继续 agents-as-tools（本次不动 Graph 化——那是未来演进）

### 改动点（精确到文件）

**① 升级** — `requirements.txt:301`、`pyproject.toml:26`、`uv.lock`
```
strands-agents==1.26.0  →  strands-agents==1.45.0
```

**②③ context_manager="auto"** — 7 个 agent、共 **8 处 `Agent(...)` 构造调用**（detect_agent 有 per-account + single 两处；main 在 `_build_agent` 闭包内），各加一个参数：
```python
# main_agent.py:264, scan/detect/rca/sre/executor/reporter 同理
Agent(
    system_prompt=...,
    model=model,
    conversation_manager=get_agent_conversation_manager("main"),  # 保留
    context_manager="auto",  # 新增：ContextOffloader 自动挂上
    tools=[...],
)
```
- **无需改 `get_agent_conversation_manager`**：Null/SlidingWindow 策略原样保留。
- offloader 用 SDK 默认 InMemoryStorage（进程内，20 cycle 自动回收）——符合"最简单方案"，不引入磁盘/S3 依赖。
- 加一个 config 开关 `strands_context_manager_auto`（默认 True），可一键回退。

**④ HumanInTheLoop** — `executor_agent.py:228`（仅 executor，并行加层）：
```python
from strands.interventions import HumanInTheLoop  # 升级后可用

agent = Agent(
    system_prompt=...,
    model=model,
    callback_handler=None,
    conversation_manager=get_agent_conversation_manager("executor"),
    context_manager="auto",
    interventions=[HumanInTheLoop(
        allowed_tools=["get_approved_fix_plan", "run_aws_cli_readonly"],  # 只读放行
        ask=<复用现有审批回调 / 或 interrupt-resume>,
    )] if settings.executor_hitl_enabled else [],
    tools=[...],
)
```
- **不拆旧逻辑**：现有 `get_approved_fix_plan` gate（executor_agent.py:66）+ DB 状态机 + L0/L1 分级全部保留。
- HITL 是**额外的第二道 SDK 级门**，默认由 config `executor_hitl_enabled`（默认 **False**，先安全上线，验证后再开）控制。
- `ask` 模式待定：CLI 用 `ask="stdio"`；Web/自动流水线用 interrupt/resume。第一版先做 **interrupt/resume**（最通用，不阻塞），接线到现有审批 UI 留作后续。

## 4. 分步实施 + E2E 验证（每步独立可回滚）

验证标准（已确认）：**分层——全量 pytest 保回归 + 关键项真实 Bedrock 冒烟**。

| 步 | 动作 | E2E 验证 | commit |
|---|---|---|---|
| **0** | 升级依赖 1.26→1.45 | `pip install` 成功 + `python -m pytest tests/ -x`（164 文件全绿）+ `aiops chat "check health"` 真实 Bedrock 冒烟 | `chore(deps): strands 1.26→1.45` |
| **1** | ②③ 7 agent 加 `context_manager="auto"` + config 开关 | 全量 pytest 绿 + `aiops chat` 触发一次大输出（如全量 scan）验证 offloader 不报错、结果正常 | `feat(agents): context_manager=auto` |
| **2** | ④ executor 加 HumanInTheLoop（默认关） | 全量 pytest 绿 + 开关 True 时 `aiops chat` 走一次 L0/L1 fix 验证审批门触发；开关 False 时行为不变 | `feat(executor): optional HITL gate` |

每步之间：**你确认后才 commit**（`git push --no-verify`，且按你铁律"E2E + 主人确认后再推"）。

### 回滚
- 每项独立 commit → `git revert <sha>` 即回退单项。
- ②③④ 均有 config 开关 → 不改代码也能运行时关掉。
- 步 0 若破坏面超预期 → `requirements.txt` 改回 1.26.0 重装。

## 6. 风险与缓解

| 风险 | 级别 | 缓解 |
|---|---|---|
| 跨 19 个 minor 版本有隐性行为变化 | 中 | 步 0 全量 pytest + 真实冒烟；破坏面已核实仅 Mistral |
| `context_manager="auto"` 改变 token 计费/缓存行为 | 中 | config 开关默认可关；先灰度对比 token 曲线（cost_service 已有） |
| ContextOffloader 的 `retrieve_offloaded_content` 工具干扰现有 tool 调用 | 低 | InMemoryStorage 默认；pytest 覆盖 + 冒烟观察 |
| HITL interrupt 阻塞自动流水线 | 中 | 默认 `executor_hitl_enabled=False`；先 interrupt/resume 不阻塞式，验证后再接 UI |
| prompt-cache 因新 plugin 注入被破坏 | 低 | offloader 只在 tool 结果超阈值时介入，不改 system prompt |
