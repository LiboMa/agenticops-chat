- 选方向：「you can use A, strategy.」（三个方向里的 A：安静的清单 + 数字）
- 「感觉这个代办工作台和问题本身没有什么区别；是否可以融合成一个？」

预览（git 忽略的 `.superpowers/brainstorm/22516-1794302528/content/`）：`nav-daily-v4.html`（三个方向）、`nav-full-a-v2.html`（A 用到整个侧栏，含数字规则表）、`issues-merge-v1.html`（合并后的「问题」）。

上位设计的「全局约束」照旧适用：`2026-11-08-mvp-2.8.0-workspace-redesign-design.md`。

## 为什么

现在的侧栏是一列图标加名字，只有「问题」上一个红点，说不出有多少、是什么。主人要的是简约、好用、有交互：一眼看出哪里有事在等、多少件、急不急；不想要的花样一律不加。

待办工作台和问题列表里有大量重复（问题的「待我处理 / 执行失败 / 长时间等待」视图就是工作台的内容），两个入口让人不知道该去哪。合成一个，侧栏少一项。

成功的样子：
- 打开 AgenticOps，看侧栏就知道哪里有事、多少件、有没有严重的；
- 所有在等我的事（问题和变更）在一个地方，按要做的决定分组；
- 收藏的旧链接（工作台）不会坏。

反目标：
- 数字不准（例如把只读账户批不了的事也算进去、同一个数在两处却对不上）；
- 数字加载失败时显示 0 或空白，让人以为没事；
- 为了好看加动画、加颜色，反而更乱；
- 合并以后找不到原来工作台里的变更待办。

## 1. 侧栏（方向 A，三块通用）

- **结构不变**：日常工作（总是展开）、运行管理（可折叠）、管理（贴底，不折叠）；拖动排序、手机菜单照旧。
- **当前页**：浅蓝底 + 左边一条 3 px 蓝色竖线，图标和文字是主色。
- **悬停 / 键盘聚焦 / 当前页**：名称下面多一行小字，说明这一项现在的情况（例如「6 件在等你，1 件严重」「1 个最近一次失败」「修复方案、变更和审计」）。这行字也是这一项的无障碍描述的一部分，读屏能读出数字的意思。
- **数字**（每项最多一个，右对齐，等宽数字）：

  | 条目 | 数字 | 颜色 |
  |---|---|---|
  | 问题 | 在等你的事项数（原来工作台的数，包括变更） | 实心蓝；其中有严重的问题时实心红 |
  | 方案与变更 | 不显示（我的决定：在等你批准的方案和变更已经算在「问题」里，再显示一次就重复了） | — |
  | 安全 | 未结的高危和严重安全发现数 | 普通灰色数字 |
  | 定时任务 | 最近一次运行失败的定时任务数 | 红色 |
  | 技能 | 在等审核发布的技能草稿数 | 普通灰色数字 |
  | 其余 | 不显示数字，只有说明小字 | — |

  - 数字为 0 时不显示；
  - 数字是「要有人去处理的事」：只读账户什么都处理不了，所以**只读账户的侧栏不显示数字**（我的决定，审阅者提出），说明小字照常；
  - 「问题」和「安全」可能数到同一条安全发现（它在等你批准，又是未结的高危）——两个数说的是两件事：「问题」= 在等你做决定的，「安全」= 还没解决的高危发现，各自和点进去的页面一致，不去重（我的决定，审阅者提出）；
  - 只有「问题」的数字跟着顶栏的账户范围（它点进去的页面也跟着）；安全、定时任务、技能的页面不按账户筛，它们的数字也不按（我的决定，审阅者提出）；
  - 没有数字的条目，说明小字是固定的文字（预览里的「1,284 个」「3 个用户」只是示例，不做实时数）；
  - 拿不到数字（请求失败）时不显示数字，说明小字写「暂时拿不到数字」，绝不显示 0；
  - 和顶栏「需要你处理」同一个数、同一个刷新节奏（30 秒），两处永远一致。
- **折叠的「运行管理」**：折叠时，如果里面有红色数字，标题旁留这个红色数字（例如定时任务失败 1 个），不会因为折叠就看不到失败。
- **动画**：只有说明小字的展开（0.15 秒）；系统设置了「减少动态效果」时不做。
- **侧栏的顺序**：日常工作是 问题、对话、方案与变更、安全、报告（「待办工作台」去掉，问题排第一）。浏览器里存着的顺序（我的决定，审阅者提出：第一次打开侧栏就会把默认顺序存下来，所以几乎每个浏览器都有「存过的顺序」）：「问题」挪到原来「待办工作台」的位置，其余保持原来的先后。存的是 S2 的默认顺序时，结果就是新的默认顺序（问题第一）。

## 2. 「问题」页合并待办工作台

- **标签**：在等我（默认）、全部、执行失败、等了很久，每个带数字。
  - 「在等我」= 原来待办工作台的全部内容：在等你的问题**和变更**；数字 = 侧栏「问题」的数字。
  - 「全部」「执行失败」「等了很久」= 现在问题列表的同名视图（只有问题）。原来的「待我处理」视图去掉（被「在等我」取代）。
- **「在等我」的列表**：
  - 原来工作台的五个标签改成**分组**，一个列表从上到下：待你批准、待你验收、执行失败（含批准了但没开始的）、待你确认（含需要补充说明的）；每组标题带数量，没有就不显示这一组；组内等得最久的在前。
  - 变更带「变更」标记和 `C#n`；点开右边显示变更自己的页面，问题显示问题自己的页面。
  - 搜索、顶栏的账户范围照旧生效；一次加载 50 条，下面「加载更多」。
  - 处理完的那一项照旧提示「已处理」并给出下一项（工作台原有的做法）。
- **宽屏**（≥ 1280 px）：列表在左，选中的事项在右（问题或变更的页面）；窄屏：列表和事项轮流全屏，「返回」回到同一个标签、同一个滚动位置。选中哪一项记在地址里，刷新后还在。
- **只读账户**：「在等我」永远是空的，所以打开「问题」默认到「全部」；「在等我」标签仍在，空状态写明「只读账户没有需要你处理的事」。
- **旧地址**：`/app/inbox`（带不带参数）转到「问题 · 在等我」，原来的搜索词和选中项一起带过去；固定首页、上次访问的页面如果是工作台，同样转过去。
- **顶栏「需要你处理」**：点了到「问题 · 在等我」。

## 3. 后端

- 侧栏的数字用**一个请求**拿到（我的决定，避免侧栏每 30 秒发好几个请求）：新接口 `GET /api/ui/nav-counts`（普通 `def`），返回这个人的「在等你」总数、其中严重问题的数量、安全高危发现数、失败的定时任务数、待审技能草稿数。「在等你」按 `services/attention` 现有的定义和权限算，和 `/api/ui/attention` 同源；跟着顶栏账户范围（`account_id`）。
- 「在等我」列表用现有的 `GET /api/ui/attention`（它已经有每个原因的数量、搜索、分页），加一个排序 `sort=decision`：先按组（待你批准、待你验收、执行失败、待你确认），组内等得最久的在前。这样一页一页加载时，新的条目只会接在最后一组后面，已经显示的组不会被插进新条目（我的决定，审阅者提出）。

## 测试

- 单元测试：
  - 数字规则：0 不显示、拿不到不显示、严重时变红、折叠时红色数字上浮到标题；
  - `nav-counts` 和 `/api/ui/attention` 的总数一致；只读账户在等他的数是 0；跟着账户范围；
  - 保存过的侧栏顺序去掉 `inbox` 后其余顺序不变；
  - `/app/inbox?...` 的转址带上搜索词和选中项；
  - 「在等我」的分组（原因 → 组）和组内顺序。
- E2E（:8001，1440 / 1280 / 1024 / 390 / 320 px，管理员、可写、只读三种账户）：侧栏数字与顶栏一致；悬停 / 聚焦显示说明；折叠后红色数字还在；「在等我」里点问题和变更都能在右边处理；旧工作台链接转址；键盘能走完整个侧栏。
