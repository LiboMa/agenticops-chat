上位设计：`docs/superpowers/specs/2026-11-08-mvp-2.8.0-workspace-redesign-design.md`，它的「全局约束」全部照旧适用。

## 顺序（主人 2026-11-09 定）

1. **S2 布局返工**：侧栏、对话页、对话里的统计。
2. **用户管理页**。
3. **MCP 对接**：用户自己的 API Key 管理加上 AgenticOps 的 MCP 服务端。**不在本文件里**，另开一轮先问清楚、出预览、再写设计。

## 为什么

主人点名的问题：
- 「运行管理」和「管理」里的选项放错了组：设置夹在运行管理中间，运行总览、Agent 指标、全景图、技能却在管理里。
- 对话页把侧栏收成 56 px 的图标栏，图标分不清组。
- 对话里统计数字总是画成柱状图、饼图，费 token。

成功的样子：侧栏一眼能找到东西，点哪里落到哪里，各种屏幕宽度下都不错位、不溢出；对话回答默认简洁省 token。

反目标：
- 改完以后又冒出新的错位、空白页、点了没反应、返回回不到原处。主人原话是「做好前端交互测试，不要有Bug」。
- 为了省 token 用字符拼出来的条形图（主人在 A 表格 / B 文字条形图之间选了 A）。

## 1. 侧栏

### 分组（主人定）

| 分组 | 条目，按顺序 | 行为 |
|---|---|---|
| 日常工作 | 待办工作台、对话、问题、方案与变更、安全、报告 | 不变，始终展开 |
| 运行管理（`tools`） | 运行总览、全景图、定时任务、资源、Agent 指标、技能 | 可折叠，和现在一样 |
| 管理（`administration`） | 用户管理（新）、设置 | **贴在侧栏最下面**（在「首页与语言」之上），**不折叠**；设置是最后一项 |

- 「运行管理」的前四项是主人给的顺序。Agent 指标、技能放在后面：Agent 指标是我的猜测，主人在预览里看过没有反对；技能是主人指定的。
- 「用户管理」只有管理员看得到。「设置」照现在的规则：可写用户和管理员看得到，只读账户只有带 `settings_read` 时看得到（`lib/permissions.navItemVisible`）。「管理」组一项都看不到时，整个组不显示。
- 组 id 不变（偏好接口的 `nav_groups_open` 仍用 `tools` / `administration`）。`administration` 不再折叠，存着的「打开 / 关闭」状态对它不起作用。
- 已经存过自定义顺序的用户（`aiops-nav-order-v2`）：没挪组的条目，组内原来的先后不变；被挪了组的条目（运行总览、Agent 指标、技能、全景图进运行管理，设置进管理）和新条目（用户管理）放在新组里的默认位置。2.7.0 以前的 v1 顺序也一样迁移。沿用 `normalizeOrder` / `migrateNavOrder` 的现有做法，不加新的存储 key。（我的决定：挪组的条目不跨组保留原来的先后——那要跨组查找，S2 的迁移测试也是这样钉的。）
- 拖动排序只在组内，和现在一样。
- 手机菜单（800 px 及以下，顶栏里的菜单）用同一套分组和可见规则。

### 对话页不再收成图标栏

- 宽度大于 800 px 时，对话页和其他页面一样显示完整侧栏（801–1100 px 是 166 px 宽，更宽是 200 px），删掉对话页专用的 56 px 图标栏和它的「展开」浮层。
- 800 px 及以下保持现在的样子：侧栏是顶栏菜单，会话列表 768 px 以下是抽屉。
- **会话列表（主人 2026-11-09 定）**：
  - 1280 px 及以上：照旧和对话并排，默认打开，可以收起，可以拖动宽度（`aiops-chat-list-open` 和宽度的存储不变）。
  - 801–1279 px：不并排。点「会话」从左边滑出，盖在对话上（弹层规则：滑入、ESC、点外面关闭、焦点回到「会话」按钮）；选好会话、新建对话后自动收起。这个宽度下不读也不改 `aiops-chat-list-open`。对话区在 801 px 时约 630 px。
  - 800 px 及以下：照旧，768 px 以下是现在的抽屉。
  - 1280 px 和问题页从「并排」切到「轮流全屏」的宽度相同（`SPLIT_MEDIA`）。

## 2. 对话里的统计、图表和流程图

只改网页对话那一版主代理（`create_main_agent(rich_output=True)`）提示词里的 `RICH_OUTPUT_PROMPT`，其他不动：

- **统计、对比、分布、趋势的数字，默认写成一句结论加一个 markdown 表格。** 不输出 `chart` 块，也不用字符拼条形图。
- **只有用户明确要求图表时**（「画个图」「用柱状图 / 饼图 / 折线图」、"chart"、"plot" 之类，任何语言），才输出一个 `chart` 块。格式和限制不变：JSON，最多 8 个系列、50 个点，只画从工具或上下文拿到的真实数字。
- **流程、调用链、依赖路径、步骤顺序照旧画成 mermaid flowchart**（或 sequenceDiagram），规则不变。
- 命令行、IM、定时任务、报告代理照旧不带这段规则（`tests/test_main_agent_rich_output.py` 已经钉住）。
- 前端不改：对话里收到 `chart` 块照旧渲染，以前存下的图表照旧显示。
- 提示词保持英文、长度有上限（现有测试已经钉住）。

## 3. 用户管理页（新）

主人确认的范围：管理员在网页上看所有用户，新建用户并选身份，停用、重新启用、改身份；多加的「重置密码」主人同意保留（「包括重置密码，除非你不要」→「可以的」）。

### 身份（沿用现在 `aiops users` 的四种）

| 身份 | 存储 |
|---|---|
| 管理员 | `is_admin = true`，`permissions = ["read","write","admin"]` |
| 可写 | `permissions = ["read","write"]` |
| 只读 | `permissions = ["read"]` |
| 只读，可查看设置 | `permissions = ["read","settings_read"]` |

界面上新建或改身份时是三个选项（管理员 / 可写 / 只读）；选「只读」时多一个勾选「可只读查看设置」。

### 页面 `/app/users`（照预览）

- 只有管理员能打开，其他人得到 404 页（和设置页的做法一样）。
- 页头：标题「用户管理」，一句说明，按钮「新建用户」。
- 搜索（名字或登录名）、身份筛选、状态筛选，都在浏览器里做（用户不会多）。
- 表格：用户（显示名 + 登录名，自己那一行标「你」）、身份、状态（正常 / 已停用，用文字）、最近登录（UTC，「从未登录」）、操作。手机上表格变成一行一张卡片。
- 每行操作：改身份、重置密码、停用；已停用的只有「重新启用」。自己那一行只有「重置密码」。
- **新建**对话框：登录名、显示名（可选）、身份。创建后显示「已创建 xxx」和系统生成的初始密码，只显示这一次，带「复制」按钮，按钮写「我已复制，关闭」。
- **重置密码**：先确认，再像新建一样只显示一次新密码。
- **停用**：先确认，写明「这个用户已经登录的浏览器会立刻退出」。
- 四种数据状态、16 px 移动端输入框、弹层规则（滑入、ESC、焦点约束、关闭后焦点回到打开它的按钮）、双语文案，都按全局约束。
- 认证没开时（`api_auth_enabled=false`）：网页本身仍然要登录（`RequireAuth`、`/api/ui/bootstrap` 两种模式下都校验会话），所以停用、重置密码照样会把人挡在外面；不生效的是身份限制（只读、只许管理员）。页面顶部写明「当前未开启接口认证：所有已登录的人都按管理员处理，身份限制不生效」。（我的决定，修正了预览里的说法。）

### 接口（新，都是普通 `def`，只许管理员）

| 接口 | 作用 |
|---|---|
| `GET /api/users` | 所有用户：`id, email, name, role, settings_view, is_active, last_login_at, created_at`，按登录名排序 |
| `POST /api/users` | `{email, name?, role, settings_view?}` → `{user, password}`，密码由服务端生成（同 CLI：`secrets.token_urlsafe(12)`），只在这次返回 |
| `PATCH /api/users/{id}` | `{role?, settings_view?, is_active?}` → 更新后的用户 |
| `POST /api/users/{id}/reset-password` | → `{password}`，只在这次返回 |

- **管理员判定始终生效**，不受 RBAC 影子模式影响：开启认证时必须是管理员，用 API Key 时 Key 也要带 `admin`（照 `routers/upload_settings._can_edit` 的写法）。未开认证时放行。非管理员一律 403。
- **保护**：不能停用或降级自己（409）；最后一个启用中的管理员不能被停用或降级（409）；登录名重复 409；登录名为空或超长 422；用户不存在 404。「自己」是请求里 Bearer 令牌解析出的用户，认证开不开都这样认（照 `/api/ui/bootstrap` 的做法），所以认证关闭时保护照样生效，审计也记真实用户。
- **生效时间**（我的决定）：
  - 停用：删除这个用户的所有登录会话，并作废他的所有 API Key（`is_active=false`，不是只靠用户被停用来挡）。重新启用后旧 Key 不会恢复，要重新发；重新启用时也清掉残留的会话（命令行 `aiops users disable` 不删会话）。
  - 重置密码：删除这个用户的所有登录会话；**重置的是自己时，保留发起这次请求的那个会话**，只让其他浏览器退出——否则新密码还没复制，自己就先被 401 送回登录页。
  - 改身份：下一次请求生效。会话每次请求都重新读用户行（`AuthService.validate_session`），对话代理的缓存在只读状态变化时也会重建（`session_manager._cached`）。`validate_api_key` 已经检查 `is_active`。
- **审计**：每次新建、改身份、停用、启用、重置密码都写一条 `audit_logs`（`AuditService.log`，实体类型 `user`），记执行人和身份的前后值，**从不记密码**。
- 命令行 `aiops users` 和它的行为不变。

## 测试（主人要求「做好前端交互测试，不要有Bug」）

除了每个任务的单元测试，E2E 在 :8001 实例（副本库，定时任务全停，开启认证）上用真实浏览器做，宽度 1440 / 1280 / 1024 / 801 / 800 / 768 / 390 / 320 px：

- 侧栏的每一项都点一遍：落到对的页面，高亮对的那一项，面包屑对；折叠和展开运行管理；组内拖动；手机菜单里也点一遍。
- 管理员、可写、只读、只读 + 查看设置四种账户各看一遍侧栏和 `/app/users`（非管理员直接打开是 404）。
- 往浏览器里写一份旧的自定义顺序（S2 之前的 v2，和 2.7.0 以前的 v1），刷新后条目在新组里。
- 对话页在每个宽度下：侧栏完整、会话列表开关、手机抽屉、输入框宽度。
- 用户管理全流程：新建（密码只显示一次、能复制）、改身份后对方下一次请求生效、停用后对方浏览器立刻退出、重新启用、重置密码后旧会话失效、自己那一行不能停用 / 降级、最后一个管理员受保护、审计里有记录而且没有密码。
- 真实模型对话（:8001 实例）：问资源统计，回答是表格不是图表；说「画个柱状图」，回答带图表；问修复流程，回答是流程图。
- 每个页面：浏览器控制台没有错误，没有整页横向溢出，四种数据状态（拦截接口返回 503，显示错误而不是空）。
- 之后整个分支评审一次，修复一轮，每个修复先有一个会失败的测试。
