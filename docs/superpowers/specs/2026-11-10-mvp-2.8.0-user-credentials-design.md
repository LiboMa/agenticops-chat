# MVP-2.8.0 用户管理里的密码与密钥 + 删除用户（设计）

2026-11-10。主人的原话：
- 「把生成API-Keys 和User Management那一页集成起来；即：用户可以像修改密码一样，生成Key、更新Key，以及删除key，此外，Admin user可以删除用户」
- 「就是生成密钥，修改密码放一排」
- 「生成密钥、修改密码相关的操作，尽可能使用Icon化的按钮」
- 「按推荐的方式来」（第 ⑤ 题：其余操作也用图标）
- 「把用户不用的全部删除掉」

预览（git 忽略的 `.superpowers/brainstorm/22516-1794302528/content/users-keys-v1.html` 与 `users-keys-v3.html`）里主人的选择：
1. 一个人可以有多个密钥（不是一人一个）。
2. 「更新密钥」= 换一个新的：生成新密钥（只显示一次），旧的立即失效。
3. 头像菜单里的「我的 API 密钥」保留，自己也能管。
4. 删除用户时保留他的对话和报告，署名改为「已删除的用户」。
5. 用户行里的所有操作都用图标按钮。

上位设计：`2026-11-08-mvp-2.8.0-workspace-redesign-design.md` 的「全局约束」，以及 `2026-11-10-mvp-2.8.0-api-keys-design.md` 已实现的全部 Key 规则（只读 Key 名副其实、Key 不做人的决定、Key 不管 Key / 密码 / 用户、降级时 Key 一并降成只读、审计不记 Key）。本设计只改下面写到的地方。

## 为什么

管理员现在在用户管理里给人建账号、重置密码；Key 却只能本人去头像菜单里建。主人要的是一个地方管一个人的全部凭证：在他那一行重置密码、生成密钥，和重置密码一样把新密钥交给他。另外，管理员需要删掉不再用的账号，而现在只能停用。

成功的样子：
- 管理员在用户那一行一次就找到密码和密钥的操作；
- 一个人可以给不同的应用各发一个密钥，单独更新或删除；
- 删掉的人登不进来、密钥全失效，但他留下的对话、报告和审计都还在，也不会因此变得别人能看。

反目标：
- 删除用户以后，他的私有对话或报告变成所有人可见；
- 更新密钥以后旧密钥还能用；
- 管理员给别人生成的密钥超过那个人自己的身份；
- 用图标以后，有人分不清哪个按钮是做什么的（没有文字说明、读屏读不出来）。

## 1. 用户管理页（`/app/users`，仍然只有管理员能打开）

- **每行的操作全部是图标按钮**（lucide 图标，和项目已有的一致）：
  - 凭证一组：重置密码（`RectangleEllipsis`）、生成密钥（`KeyRound` 加一个小加号）。
  - 竖线隔开。
  - 账户一组：改身份（`UserCog`）、停用（`Ban`，红色；已停用的是「重新启用」`UserCheck`，不是红色）、删除用户（`Trash2`，红色）。
  - 每个图标按钮：鼠标移上去或键盘聚焦时显示文字说明；`aria-label` 是同样的文字；桌面 32 px，手机 40 px；有可见的焦点框。
  - 自己那一行只有重置密码、生成密钥；最后一个启用中的管理员不能被停用、降级或删除（服务端照旧拒绝，页面也不给按钮）。
- **「API 密钥」一列**：写「N 个有效 ▸」或「无」，N 是有效且未过期的数量；点了打开这个人的密钥列表。
- **这个人的密钥列表（对话框）**：
  - 标题旁一个「生成密钥」图标按钮；
  - 每个密钥一行：名称、前缀、权限、最近使用、到期、状态（有效 / 已过期），右边两个图标按钮：更新密钥（`RotateCcwKey`）、删除密钥（`Trash2`，红色）；
  - 已删除（撤销）的密钥不再出现在列表里。
- **生成密钥对话框**：名称（必填）、权限（只读 / 读写；那个人是只读账户时「读写」不能选并写明原因）、有效期（30 天 / 90 天 / 1 年 / 永不过期，默认 90 天）。
- **新密钥只显示一次**：和一次性密码同一套做法，标题写明是谁的哪个密钥，一个复制图标按钮，「我已复制，关闭」，点外面不关，关闭后连请求缓存一起清掉，焦点回到打开它的按钮。
- **删除用户确认框**：写明删掉什么（登录、所有会话、全部 API 密钥、未发送的附件，立即失效）、保留什么（他的对话、报告和审计记录，谁能看不变），登录名以后不能再用，以及不能恢复。

## 2. 「我的 API 密钥」（头像菜单，保留）

- 页面主按钮保留文字「新建 API 密钥」。
- 每个密钥一行，右边同样两个图标按钮：更新、删除。
- 已删除的密钥不再显示。

## 3. 规则

- **更新密钥 = 换一个新的**：生成新密钥（只显示一次），旧的立即失效；名称不变，权限和有效期重新选（默认沿用原来的，权限不超过那个人当前的身份）。本人和管理员都能更新；用 API Key 认证的请求不能更新（和建、删一样，`session_required`）。
- **只读账户也能更新自己的密钥**（我的决定，审阅者提出）：只读账户本来就能建、删自己的（只读）密钥，更新就是这两步合在一起，所以本人更新的接口加进只读账户的写白名单；新密钥照样只能是只读。
- **删除密钥**：立即失效，从列表里拿掉；审计里留记录。
- **管理员给别人生成密钥**（这推翻了上一轮的「管理员不能替别人新建 Key」，主人 2026-11-10 定）：权限不超过那个人的身份（只读账户只有只读），从不带 `admin`；完整的密钥只在这一次返回给管理员；审计记下是谁给谁生成的。
- **删除用户**：
  - 只有管理员；不能删自己（409 `self_change`），不能删最后一个启用中的管理员（409 `last_admin`），和停用的规则一样；只能用登录会话，不能用 API Key。
  - 立即删掉他的所有会话和 API 密钥。
  - 他留下的对话、报告、审计记录都保留，**可见范围不变**：私有的对话和报告仍然只有原来能看的人能看（也就是管理员），绝不能因为主人没了而变成所有人可见。
  - 列表里不再显示这个人。
  - **登录名不能再用**（我的决定，审阅者提出）：系统里很多记录按登录名记人（变更的发起人 `requested_by`、批准人、验收人、备注、审计里的执行人、未发送的对话附件），同名的新账户会「继承」旧人的待办和权限（例如能取消旧人的变更请求）。所以删除后这个登录名保留给旧记录；用同一个名字新建账户返回 409，码 `name_taken_by_deleted`，提示换一个名字。
  - **他还有在等他处理的变更请求时不能删**（我的决定，审阅者提出）：发起人在 `draft` / `needs_clarification` 状态的变更请求只出现在发起人自己的待办里，人删了就没人看得到。删除返回 409，码 `has_open_requests`，写明是哪几个；管理员可以先取消它们（管理员本来就能取消），或者改成停用。主人要删的不用的账户不会有这种请求。
  - 他未发送的对话附件一并删掉。
  - 署名：见下面「署名」一节。
  - 写一条 `user.delete` 审计，和改动在同一个事务里。
- 所有新接口和改动的接口都是普通 `def`；管理员的新接口不在只读账户的写白名单里。

## 署名（审阅者提出，2026-11-10 按推荐做法）

预览第 ④ 题选的是「保留，署名改为『已删除的用户』」。但页面上的对话和报告本来就不显示主人是谁；人名只出现在审计、批准人、验收人、动态、变更发起人这些地方（约 15 处），存的是登录名。按推荐做法：**记录照原样保留，显示原来的登录名**；因为登录名不会再被别人用（第 3 节），这个名字仍然只指那个人。不在这 15 处加「已删除的用户」字样（主人如果要，另做）。

## 4. 主人第 3 项：删掉不用的账户

本地正式库里已经只剩 `admin`。不用的 12 个测试账户（`e2e-*`）在 :8001 的副本库里：功能做好后，在副本库上用网页的「删除用户」把它们删掉，顺便当作这个功能的 E2E。`e2e-admin`（E2E 要用的管理员）最后删或保留，由实现时决定，在报告里写明。

## 测试

- 单元测试：
  - 管理员给只读账户生成读写密钥被拒；给可写账户生成的密钥能用、属于那个人、审计记着管理员；
  - 更新以后旧密钥立即 401，新密钥能用，名称不变；用 Key 认证的请求不能更新；
  - 删除密钥以后不在列表里；
  - 删除用户：会话和密钥立即失效；不能删自己、不能删最后一个管理员；他的私有对话和报告对别的非管理员仍然不可见；同一个登录名不能再新建（409 `name_taken_by_deleted`）；
  - 路由都是普通 `def`。
- E2E（:8001，1440 / 390 / 320 px）：
  - 图标按钮都有文字说明（悬停、聚焦、读屏名称）；
  - 管理员给别人生成、更新、删除密钥，新密钥只显示一次；
  - 本人在「我的 API 密钥」更新、删除；
  - 删除 12 个测试账户。

## 留给实现的

- 「删除用户」怎么存（例如加一个标记删除的列，或换一种不改表结构的办法），只要满足第 3 节：私有内容的可见范围不变、登录名不能再给别人用、署名能显示原登录名。
- 「更新密钥」是改原来那一行还是撤销旧行再建新行（审计都要能看出是一次更新）。
- 图标的具体大小、悬停文字的样式。
