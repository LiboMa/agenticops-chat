# MVP-2.8.0 工作台改版：状态可信、待办分流、安全按账号、报告全集检索、会话与登录（设计）

2026-11-08 · 分支 `MVP-2.8.0`（从 `MVP-2.7.1` = `35c4990` 切出，主人决定）· 记进新的 `docs/MVP-2.8.0-RELEASE.md`

## 为什么

v2.7.0 的线上审阅（2026-11-07，`reports/frontend-review-2026-11-07/`）发现，界面在几处地方会让人判断错，或者找不到下一步：

- 安全页请求失败时显示「没有发现」；两个账号的趋势被画成一条线；每个账号卡片都显示全局的 open 数。
- 定时任务用 `is_enabled ? "Running" : "Completed"` 推断运行状态，没跑过的任务也显示 Running。
- 待办有 205 项，却混在一个弹层里；执行完成后等人验收，这一步要往下翻长计划才看得到。
- 报告只在已加载的 50 条里搜索；会话的「显示归档」从不向服务端要归档数据。
- 窄屏下长标题撑出屏幕；13 个设置开关没有名称；全局搜索的焦点会跑出弹层。

审阅者同时给了两轮设计样本：`design-preview/`（工作台、安全、报告、定时任务、设置、移动端）和 `login-sessions-design/`（登录、配置介绍、会话列表、变更管理）。这一版把审阅的 20 条和两轮样本做进产品。数据全部用真实接口，样本里的演示数据一条也不进生产页面。

## 全局约束（每个阶段都适用）

- **颜色**：浅色主题沿用蓝白，取样本的值：
  - 页面背景 `#F6F8FC`，内容表面 `#FFFFFF`，正文 `#17243C`，次要文字 `#596B86`，主要动作 `#2863EB`；
  - 状态文字和标签：红 `#B42318`、琥珀 `#915B0A`、绿 `#167351`，背景用同色浅底。
  - 这些值通过 `index.css` 的 CSS 变量落地。现有的 `--canvas`、`--selected` 等变量名保留。
- **状态永远有文字**：成功、失败、未知、等待都要写成文字，颜色只起辅助作用。新增一个共用的状态文字组件（色调 + 文案），所有改到的页面都用它。
- **四种数据状态**：每个独立的数据模块都分别表达加载中、失败（带重试）、空、成功。
  - 「空」只在请求成功、且确实返回空集合时出现。
  - 刷新失败但手里有上次的数据时：继续显示旧数据，标出「刷新失败 · 数据截至 HH:MM UTC」，并给重试按钮。
  - 一个模块失败，不能把别的模块藏起来。
  - 新增一个共用组件实现这四种状态，改到的每个页面都用它。
- **时间**：
  - 页面上显示的每个时间都标明 UTC，写在正文里，或写在 tooltip 里。
  - 按日期分组和日期筛选的边界都按 UTC 日计算（目前报告分组用的是浏览器本地日）。
  - 用户自选时区：不做（样本说明里写的是「未来」）。
- **窄屏**：
  - 改到的每个页面在 320 px 和 390 px 下都没有整页横向溢出，即 `document.documentElement.scrollWidth <= window.innerWidth`。
  - 长标识符用 `overflow-wrap: anywhere` 换行。
  - 主要按钮至少 44 px 高。
  - 移动端的输入框字号 16 px，避免 iOS 自动放大。
- **字号**：
  - 改版页面正文 14 px，标题 21–25 px，图表和辅助标签不小于 12 px。
  - 用户的字号偏好（`ThemeProvider`）继续生效。
- **键盘与读屏**：
  - 所有交互元素都能用键盘到达，焦点可见。
  - 弹层遵守仓库的弹层规则（滑入动画 + ESC 关闭），并把焦点约束在弹层内，关闭后焦点回到触发它的元素。
  - `prefers-reduced-motion` 下不放持续动画。
- **双语**：所有新文案同时写进 `zh.json` 和 `en.json`；技术标识（ARN、命令、ID）保留原文。
- **不改的安全约束**：
  - 计划的审批、执行、验收继续绑定确切的版本、hash 和 Run。
  - 报告的语言和导出版本继续一致。
  - 只读账户（viewer）看到的写操作照旧隐藏。
  - 账户范围（顶栏）照旧作用于它过滤的页面。
- **后端**：
  - 新增或改动的列表接口都写成普通 `def`，或者用 `asyncio.to_thread`，不在 `async def` 里做阻塞的数据库或网络调用（2.7.0 S1 的单进程规则）。
  - 返回列表的接口统一成 `{items, total}`，翻页的加上 `next_cursor`，同一阶段内改完这个接口的全部调用方。
  - 不加新的后端依赖。前端只在确有需要时加依赖，并在计划里写明理由。
- **可达面**（CLAUDE.md #9）：每个阶段在计划里逐行列出 CLI / Web API / Web UI / Agent tool / Schedule / Notification 六个面，下面各阶段已经给出。

## 分阶段

八个阶段，顺序按样本说明的建议：先修状态和操作，再做待办流程，然后是安全和报告，最后做会话、登录、表格、设置和 Galaxy。每个阶段都能独立验收、独立回退。

### S1 状态可信 + 可访问性 + 定时任务的真实运行状态（R01 R03 R04 R05 R06 R12 R16 + UTC 标注）

**R01 安全页的四种数据状态**
- `Security.tsx` 里每个模块各自走共用状态组件，模块包括：评分卡片、趋势、雷达、发现、建议、攻击路径。现在除了 summary，其他模块在加载和失败时都落成 `data ?? []`，这个写法全部去掉。
- 页头加「刷新」按钮，一次重取所有模块。
- 本阶段只改状态表达，内容改造放在 S3。

**R03 窄屏长标题**
- 在 `StatusLine`、IssueDetail、ChangeDetail、PlanDetail 的标题容器上设 `min-width: 0` 和 `overflow-wrap: anywhere`。
- 窄屏下标题、状态、主按钮分行排列。

**R04 聊天输入区**
- 2.7.1 的 ChatGPT 式输入框已经是上下布局：文本框占满一行，工具栏在下面单独一行。
- 本阶段只做复核：390 px 下文本框不窄于 300 px，320 px 下不窄于 250 px，长中文、多行代码、附件同时存在时布局稳定。
- 复核发现问题才改。

**R05 开关**
- 新增一个 Switch 组件：
  - `role="switch"` + `aria-checked`；
  - `aria-labelledby` 指向设置名称，`aria-describedby` 指向说明；
  - 保存中显示禁用状态；
  - 焦点环可见；
  - 触屏上的点击区不小于 44 px。
- 替换 Settings 里所有手写的开关（General 页 13 个），以及其他页面里同类的手写开关。

**R06 全局搜索**
- `CommandPalette` 改用 Radix Dialog：打开时聚焦输入框，Tab / Shift+Tab 在弹层内循环，Esc 关闭，关闭后焦点回到触发入口。
- 语义：输入框是 `combobox`，带 `aria-controls` 和 `aria-activedescendant`；结果列表是 `listbox`；每行是 `option`，带 `aria-selected`。
- 结果数量用 `aria-live="polite"` 播报。
- 搜索请求失败时显示错误和重试，不显示「无结果」。

**R12 工具调用**
- 工作过程（`WorkSteps`）的每一行，在色点旁边加文字：运行中 / 成功 / 失败 / 结果未知。没有 outcome 的历史记录显示「结果未知」，不能暗示成功。
- 展开后照旧显示耗时和结果预览。

**R16 定时任务**
- 后端：`GET /api/schedules` 的每一行加 `last_execution`：`{id, status, started_at, completed_at, duration_ms, error_summary} | null`。
  - 用一次分组查询取每个任务最新的一条 `schedule_executions`，不对每个任务各查一次。
  - `error_summary` 最多 200 字。
- 前端按样本 `desktop-schedules.png` 分列：

  | 列 | 内容 |
  |---|---|
  | 任务与运行方式 | 名称；cron 的自然语言说明加原表达式，如「每小时 · 0 * * * *」「一次性」 |
  | 配置 | 已启用 / 已停用 |
  | 最近执行 | 运行中 / 重试中 / 成功 / 失败 / 尚未运行，加一行摘要或错误 |
  | 运行时间 · UTC | 开始或结束时间、耗时、下次运行时间 |
  | 下一步 | 查看进度 / 结果 / 错误，链到执行记录 |

  - 「运行中」只来自真实的运行记录。没有执行记录就是「尚未运行」。
  - 不发明「排队」和「取消」：后端没有这两种状态。
  - 点「立即运行」后、执行记录出现前，这一行只在本页显示一个临时的「已提交」。
- cron 的自然语言说明用前端的纯函数，覆盖常见形态（每 N 分钟、每小时第 M 分、每天 H:M、每周），认不出的形态只显示原表达式。

**UTC 标注**：落实全局约束里的时间规则。`lib/formatDate` 的输出带上 UTC；报告列表的日期分组改按 UTC 日。

**可达面**

| 面 | S1 |
|---|---|
| CLI | 非目标 |
| Web API | 做：`GET /api/schedules` 每行加 `last_execution` |
| Web UI | 做：Security 的状态、Schedules、Settings 的开关、全局搜索、工作过程、窄屏标题 |
| Agent tool | 非目标 |
| Schedule | 非目标：只读取执行记录，调度行为不变 |
| Notification | 非目标 |

**验收**
- Security 四种情形各有不同且准确的呈现：拦截请求返回 503、慢网络、成功返回空数组、正常数据；趋势失败时发现列表照常显示。
- 390 px 打开 I#1106（标题 `Execution:Kubernetes/AnomalousBehavior.ExecInPod`）无横向溢出。
- Settings 的每个开关都能通过可访问名称找到，读屏能读出开 / 关。
- 全局搜索只用键盘就能走完：Tab、Shift+Tab、↑↓、Enter、Esc，关闭后焦点回到触发入口。
- 从没运行过的 @once 任务不显示「运行中」；停用的任务不显示「已完成」。
- 没有 outcome 的历史工具调用显示「结果未知」。

### S3 安全按账号 + 发现能进入处理流程（R02 R11，样本第 6 项）

后端（`services/security_service.py`、`web/routers/security.py`）：

**summary**：每个账号一行：
- `open_findings`：只数该账号自己的问题。现在是全局数，复制到了每个账号上（已知缺陷）。注意 `SecuritySnapshot.account_id` 是字符串，`HealthIssue.account_id` 是整数外键，两者要正确对应。
- `account_name`。
- `partition`：中国区或全球，按账号的分区判断。
- `reachable_paths`、`category_scores`，以及评分时间。

**trend**：返回 `{accounts: [{account_id, account_name, points: [{day, score}]}]}`。
- 每个账号每个 UTC 日一点，取当天最后一个快照，把 1,440 条压到每个账号最多 `days` 点。
- 参数 `days` 取 7、30 或 90。
- 某个账号某天没有快照，就没有那个点，不插值。

**findings**：参数 `account_id`、`severity`（逗号列表）、`status=open|all`（默认 `open`）、`reachability`、`q`、`limit`、`offset`；返回 `{items, total}`。
- 每项加 `account_id`、`account_name`、`region`、`resource_type`、`issue_ref`。
- 排序：严重度在前，`last_seen` 在后。

**评分的采集健康度**（主人第 7 条）：
- 现状：采集器全部失败时，`score([])` 给出 100 分、全部 pass。
- 改法：
  - `collect_posture` 报告每个采集器成功还是失败；
  - 快照新增一列 `collection_health`，记录每个采集器的成功或失败，以及失败原因的摘要；
  - 失败采集器对应的控制项记为 `undetermined`，不算 pass；
  - 采集器全部失败时，这个快照没有分数（`overall_score` 为 NULL），界面显示「无法评分 · 采集失败」；
  - 部分失败时照常给分，并标「部分采集」。
- 评分仍然可复现：同一份输入，得出同一个结果。
- 历史快照不改；没有 `collection_health` 的旧快照，界面上照旧显示分数。
- 趋势里，没有分数的快照不画点。

**没有账号的安全问题**（主人第 8 条）：
- 改法：只对安全检测器（`security_poll`、`security_posture`）生效。锚定找不到资源行时，问题取采集任务运行时所用的账号。这个账号是 signal 上明确写着的，经 provider 层解析过，不是推断出来的。
- 其他来源的问题，锚定规则不变。
- 现有的这类问题，按它们的 signal 行一次性回填 `account_id`：
  - 能唯一对应到一个账户的，才回填；
  - 对应不上的，保持为空，并在迁移日志里记下数量。
- 回填不改问题的状态，也不写 `status_changed`。

前端（样本 `desktop-security.png`、`desktop-security-error.png`）：
- **账号范围**：Security 改为跟随顶栏账户范围的页面。现在它不受顶栏范围约束。

  - 建议和攻击路径两个模块保留，同样跟随范围。

### S4 报告全集检索 + 阅读目录 + 覆盖范围（R13 R14，样本第 8 项）

```
{accounts: [name], regions: [region],
 completeness: "complete" | "partial",
 partial: {truncated: int, offloaded: int, failed: int},

```

| 字段 | 怎么记 |

| `read_at` | 这次运行开始的时间。卡片上写「数据读取于 HH:MM UTC」 |

- 现有的 `POST /api/accounts/{id}/test` 每次测试都写一条。
- 新增 `POST /api/setup/verify-model`：
  - 仅管理员可用，并写审计；
  - 用 `converse_text` 对 Main 的模型发一次很小的调用，最多 16 个输出 token；
  - 结果写进 `readiness_checks`。
- 界面上「有配置」和「验证通过」分开显示。

**右侧和底部**
- 「试一次只读巡检」：打开一个新会话，输入框里预填一段只读巡检的请求（只是草稿，不自动发送），账户范围取当前范围。
- 三个折叠问答：配置需要什么权限、以后如何重新查看、什么才算「准备完成」。
- 底部三个按钮：
  - 「返回登录」：仅登录前显示；
  - 「重新检查配置」：重取 readiness，不重新跑验证；
  - 「进入工作台」：去 `/app/inbox`。

**何时出现**

- Settings 页头和用户菜单各放一个「配置介绍」入口。

### S7 资源、表格、Agent 指标（R09 R10 R17）

**R09 表格**
- 概览页的 Recent issues：先显示标题。资源只显示短 ID（ARN 的最后一段），完整标识放进 tooltip，旁边有复制按钮。列宽按标题、严重度、等待状态、账号、时间分配。
- 资源页窄屏（< 768 px）：改成卡片列表，字段为名称、类型、健康文字、账号、区域、上次观测。
- 资源页桌面：保留表格，加短 ID 和复制按钮。

**R10 资源健康的原因**
- 后端：`GET /api/resources` 每行加 `health_reason` 和 `observed_at`（即 `scanned_at`）。`health_reason` 的取值：

  | 值 | 条件 |
  |---|---|
  | `open_issue` | 有锚定在它上面的未关闭问题 |
  | `no_open_issue` | 没有未关闭问题 |
  | `stale` | 上次观测早于 2 × `resource_scan_interval_minutes` |
  | `never_observed` | `scanned_at` 为空 |
  | `absent` | 资源已消失 |

- 界面：
  - 「Unknown」改成「无已知问题」，永远不说「健康」；
  - 其他原因显示为「数据过期 · 上次观测 2 天前」「未观测」「已消失」；
  - 页头一行写「上次资源扫描 …」，链到资源扫描任务的执行记录。
- Galaxy 的四值健康不变。

**R17 Agent 指标**
- 页头加一个统一的时间范围（7 / 30 / 90 天，写进 URL），所有模块默认跟随。
- 单个模块可以覆盖页头的范围；覆盖了的模块在标题上写出自己的范围。
- RCA 准确率写成「2 / 2 人工评判正确」，样本少于 20 时加「样本较少」，另写「已评判 2 / 15 条 RCA」。
- 指标定义放进信息提示。
- 费用显示到可读的精度，如 `$12.3`，精确值放进 tooltip。

| 面 | S7 |

| CLI | 非目标 |
| Web API | 做：`/api/resources` 每行的 `health_reason`、`observed_at`；指标接口如果缺 `days` 参数就补上 |

| Agent tool | 非目标 |
| Schedule | 非目标 |

**验收**

### S8 设置信息架构 + 文案与时间全站统一 + Galaxy（R18 R19 R20）

**R18 设置**（样本 `desktop-settings.png`）
- General 分成三节，用页内锚点导航：基础运行 / 自动化与执行 / 模型配置。每节写明作用范围，如「作用范围：此部署的全部账号」。
- 高影响的开关不再点一下就保存。包括：执行器、自动修复、L0/L1 自动批准、`rbac_enforce`、标准变更自动批准、executor HITL。
  - 改动先暂存；
  - 「预览并保存变更」弹出列表，每项写「从 → 到」和影响哪些流程，确认后保存；
  - 保存后显示「已保存」。
- 低影响的开关保持即点即存。
- **保存与权限**（主人第 10 条）：`executor_enabled`、`auto_fix_enabled`、`executor_auto_approve_l0_l1`、`executor_hitl_enabled` 四个开关移进 DB 的 `runtime_settings`，做法照 `chat_upload` 和 `model_runtime`：
  - yaml 仍是默认值，DB 里的覆盖值每次读取都重新校验；
  - 开了认证时，只有管理员能改；
  - 每次修改写一行 `audit_logs`；
  - 重启后保留；
  - 所有读这四个开关的地方都改读生效值（effective），不再读进程里的 `settings` 属性。
- HITL 从下一次执行器运行开始生效，已经在跑的不受影响。
- `rbac_enforce` 和标准变更自动批准保持现状：存在 yaml，只有管理员能改，修改要审计。
- 每次设置变更都留审计记录（还没有的就补上）。设置页有入口，跳到审计里的这些记录。
- 模型配置显示：
  - 完整的 Model ID；
  - 调用区域；
  - 可用性：这个 id 是否在 `/api/models` 的列表里，这一步不调用模型；
  - 最近一次验证的结果，来自 S6，并链到配置介绍。

## 我的判断（主人可以改）

- **暗色模式**：保持 2.7.0 S2 主人定的绿色主色，只修改版页面里对比度不够的地方。样本的暗色用的是蓝色主色。
- **验收勾选记到服务端**：`confirmed_checks` 是可选参数，服务端校验后写进事件。不记的话，勾选框只是界面上的提醒。
- **覆盖信息只在 reporter 运行里记录**：`report/generator.py` 和聊天里「保存为报告」生成的报告都不带 coverage。覆盖卡片上不写记录条数，因为代码不知道条数。「数据截至」改写为「数据读取于」，取 reporter 这次运行开始的时间。
- **R15 的首屏放在阶段卡片之上**：卡片、锚点、事实栏、活动栏都保留（见 S2）。

- **侧栏的具体分组**：问题、方案与变更进日常工作；设置进运行管理，标签沿用「设置」，不叫「运行设置」，因为设置页里还有账户、消息、知识库、MCP、记忆。
- **待办标签的归并**：`execution_not_started` 归入「执行失败」；`clarification_required` 归入「待确认」。不新增等系统处理的条目。工作台只列等人的事项，和现在 attention 的定义一致，所以样本里那一行「待执行器」不出现。
- **定时任务不显示「排队」和「取消」**：后端没有这两种状态。「立即运行」之后、执行记录出现之前，只在本页显示一个临时的「已提交」。
- **报告的 coverage 是结构化字段，没有自由文本**：卡片句子按语言用模板生成，这样中英一致；历史报告不显示卡片。
- **安全分数的档位**：≥ 80「良好」，50–80「需关注」，< 50「优先核查」。只是展示用的档位，不影响评分。
- **长时间等待的阈值**：24 小时，放在 yaml 的 `attention_long_wait_hours`。
- **「样本较少」的阈值**：少于 20 条，作为前端展示规则。
- **管理员首次登录**：只有在一个启用的账户都没有时，才自动进入配置介绍。
- **验证记录用一张新表** `readiness_checks`，不往 `runtime_settings`（它存的是设置，不是结果）或账户表里塞字段。
- **字体**：继续用 2.7.0 S2 选定并打包的 Outfit，样本写的是系统字体加 PingFang SC。
- **列表接口统一成 `{items, total}`**，与 `/api/resources` 一致，不用 `X-Total-Count` 头。
- **工作台的「紧凑收件箱」**做成一个切换按钮，不单独成页。

## 不做

- 多用户与角色管理（`multiuser-rbac-design/`）。
- 用户自选时区。
- 自助找回密码、SSO。
- 跨设备同步聊天的生成状态：`activity=generating` 只反映本进程里正在进行的发送。
- 定时任务的「关联会话」：执行记录里没有会话 id，不新造。
- 保存自定义视图：用 URL 分享来代替。
- CLI 的任何界面改动。

## 反目标（技术上做对了也算失败）

- 任何一处把请求失败显示成「没有数据」或「安全」。
- 任何一处把没有结果的东西暗示成成功，包括工具调用、post-check、任务运行。
- 样本里的演示数据（205、62.5、us-west-2、Plan #225 …）出现在生产页面上。
- 改版之后，有页面从侧栏或链接都到不了。
- 批准或验收不再绑定确切的版本、hash 和 Run，或者 viewer 能看到写操作。
- 改到的页面在 390 px 下出现整页横向溢出。
