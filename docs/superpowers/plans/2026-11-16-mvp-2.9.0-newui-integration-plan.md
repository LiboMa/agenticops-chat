# 把新界面接进产品（NewUI）并对接后端 —— 计划

> 主人 2026-11-16 在 Plan Mode 批准。设计依据：`docs/design/new-ui-face/`（原型和它的 README）；设计阶段的计划：
> `docs/superpowers/plans/2026-11-11-new-ui-face-design-plan.md`。每个阶段（N0–N7）开工前另有一份细的任务清单，放在同一目录。

## Context

**你的要求（2026-11-16）**：①在前端增加一个入口 →（NewUI），把新设计的界面集成进来，同时完成和后端新版本 API 的对接；②先做好计划，之后逐步进行。

**现状**
- 新界面的设计在 `new-UI-face` 分支：一份可点击的静态原型（`docs/design/new-ui-face/`，数据是编的）。已设计好四块：**待决**（一页一个决定）、**经过**页、**现场**、**全景**（平面 + 3D，带「数据核对」）。还没设计：完整对话、报告 / 资源 / 定时任务 / 技能等资料页、设置与用户管理。
- 产品前端是 React 18 + TypeScript + TanStack Query + Tailwind（`src/agenticops/web/frontend/`）；后端最新在 `MVP-2.8.0`（`78f8cf7`，S1、S2 已验收并推送）。

**你已经定的四件事**
1. 代码放在从 `MVP-2.8.0` 新开的 **`MVP-2.9.0`** 分支，先把 `new-UI-face` 的设计稿合并进来。
2. `MVP-2.8.0` 剩下的 S3–S8：**前端部分暂停**；改数据、改接口的部分并到新界面对应的阶段里做。
3. **先把设计好的四块接上真数据**；没设计的部分在新界面里先链接回旧页面（新旧并存）。
4. **先只接已有接口**；后端还没有的能力，对应的控件先不显示，列成清单以后逐个立项。

**做完之后**：旧界面里有一个入口进新界面（`/app/new`）；在新界面里用真数据完成「看到在等我的事 → 读简报 → 做决定」，能看一件事的经过、现在谁在做什么、全部资源的图（平面和 3D）；随时能回到旧界面，旧界面除了多一个入口不变。

## 不做什么

- 不删、不改旧页面的行为。
- 不新做后端能力（见「后端缺口」）。唯一的例外是一处**只读**字段，可以划掉（见做法 8）。
- 没设计的页面不在这一轮实现；每一块都先出设计、给你预览，再实现。
- 不推送，直到你验收当前阶段。

## 做法

### 1. 分支和工作区
- `git worktree add .worktrees/mvp-2.9.0 -b MVP-2.9.0 origin/MVP-2.8.0`，再 `git merge --no-ff new-UI-face`（只带进设计稿和截图，不会冲突）；前端在这个工作区里自己 `npm ci`。
- 测试脚本 `.superpowers/aiops-pytest.sh` 不在 git 里，而且写死了 2.8.0 工作区的路径和测试库：新工作区放一份自己的（路径改成 `.worktrees/mvp-2.9.0`，测试库改成 `/tmp/aiops-290-test.db`），不和另一个会话共用。
- `new-UI-face` 保持「只有设计」，以后没设计的页面继续在那里出稿。
- 开工时告诉另一个会话：2.8.0 的 S3–S8 前端部分暂停（你的决定），以及这条分支碰哪些路径。

### 2. 入口、路由、外壳
- **路由** `/app/new/*`：在 `src/App.tsx` 里和 `/app/login` 一样放在旧外壳（`AppShell`）之外，由同文件里的 `RequireAuth` 保护，整套懒加载。子路由：`/app/new`（待决）、`decide/:item?`、`story/:item`、`live/:id?`、`world/:view?`。后端对 `/app/*` 有回落，不用改服务端。
- **旧界面里的入口**（建议；N0 预览时可以挪）：侧栏 logo 下方一个固定的「新界面 NewUI」（不进可拖动的分组，所以不动导航顺序和它的测试）；头像菜单和手机菜单里各一项。
- **新界面里**：右上角常驻「回到旧版」（去 `/app`）。对话、报告、设置等没设计的去处是链接，点了进旧页面。
- **外壳之外要自己补的**（旧外壳提供、新界面拿不到的）：页面标题、语言切换、我的 API Key、退出登录、只读标记、`ShellEffects`（语言与偏好同步）、账户范围的选择器（现有的那个在 `/app/new` 下是禁用的，新界面用 `useAccountScope()` 自己画一个）。

### 3. 代码放哪、怎么写
- **用 React + TypeScript 重写，不嵌入静态原型。** 原型留作设计依据；它的规则搬成有类型、有测试的代码。
- 目录 `src/agenticops/web/frontend/src/newui/`：`lib/`（纯函数，全部有 vitest 测试，测试放 `src/__tests__/newui*.test.ts`——沿用现有约定：只测纯逻辑）、`shell/`、`decide/`、`story/`、`live/`、`world/`（组件，尽量薄）、`hooks/`（只做组合）。
- **样式** `newui/newui.css`：原型的样式整体搬过来。**每一条选择器都以 `.nf` 开头，动画名以 `nf-` 开头**，并有一条测试挡住例外——懒加载的样式一旦加载就不会卸载，不收住会改坏旧页面（原型里有 `main{position:fixed}` 这样的规则）。反方向，旧工程对输入框、焦点、标题的基础样式会压到新界面上，N0 逐屏对照原型截图校正。
- **文字**：新界面自己的 `newui/locales/{zh,en}.json`，随新界面的分包加载，有自己的「中英文键一致」测试；带变量的取词函数 `useNfT()`。不往现有的 `en.json` / `zh.json` 里加（那两份是首屏包的一部分），旧文件只加入口的两三个词。
- **主题**：跟随现有的明暗设置（暗 → 夜间，明 → 白天）。
- **键盘**：单键快捷键只在这些都成立时生效——不在输入法组字中、没按修饰键、焦点不在输入框、没有打开的对话框或菜单；空格和回车不抢已聚焦按钮的激活。提供一个「关闭单键快捷键」的开关。
- **按住批准**：按下时记住目标（哪件事、哪份方案、内容哈希），到时只对**还在屏幕上的同一个目标**生效；窗口失焦、切到后台、按了别的键都取消。队列每 30 秒刷新会重排，不这样做可能批到另一件事。
- **直接复用、不重写**（`src/agenticops/web/frontend/src/`）：
  - 取数：`api/client.ts`；`hooks/` 里的 `useAttention`、`useNavCounts`、`useAnomaly`、`useAnomalyRca`、`useIssueTimeline` / `useAddIssueNote`、`useIssueExecutions`、`useFixPlans`（含批准 / 退回 / 执行）、`useFixExecutions`（含验收）、`useChanges`（`useChange` / `useChangeAction`）、`useIssueActions`、`useSignals.useRcaFeedback`、`useAgentMemory.useIssueFeedback`、`useGraphFocus`、`useGalaxy*`、`useResource`、`useBootstrap`、`useExecutorStatus`、`useSettings`。
  - 规则：`lib/inbox`、`lib/attention`、`lib/issuePhases`（含 `currentFixPlan`）、`lib/changePhases`、`lib/changeDetail`、`lib/runSummary`、`lib/acceptChecklist`、`lib/approval`、`lib/verdict`、`lib/rcaQuality`、`lib/formatDate`、`lib/queryState`、`lib/galaxyHealth`、`lib/placeholders`、`lib/contextRef`、`lib/composerKeys`。

### 4. 待决：数据怎么对上
- **队列**：`GET /api/ui/attention?sort=severity`（和设计的排法一致：先严重度，再等得久的），分页取；四个筛选用 `reason` 参数，数量用返回的 `counts`。新 hook `useDecideQueue` 放在现有缓存键 `["ui-attention", …]` 下，这样每个决定之后它会跟着刷新。
- **情形 → 简报**：后端实际给出的组合是 **17 种**（比设计稿的 15 种多两种：没有诊断、诊断过关但没人确认）。纯函数 `briefKind(item)` 按「对象 + 原因 + 细分」判定到 11 种简报之一；同一种简报里的变体（检查全过 / 没有结论，步骤失败 / 检查失败 / 验收被拒）看取回来的执行和诊断再分。配一份前后端共用的清单 `tests/fixtures/attention_brief_kinds.json`：后端测试保证「可能给出的每一种组合都在清单里」，前端测试保证「清单里每一种都有简报」。认不出的组合显示通用简报（要你做什么、等了多久、哪个资源、去旧页面的链接），不留白。
- **每种简报能做的决定**（全部是已有接口）：

| 简报 | 主要动作 | 其他动作 | 先不显示 |
|---|---|---|---|
| 批准（问题 / 变更） | 按住批准，带当时看到的内容哈希；变更的批准后端要求写理由，所以先填理由再按住 | 退回方案（写理由）；忽略问题 / 拒绝变更 | 要求修改、稍后、和上一版的差别 |
| 验收（问题 / 变更） | 逐项打勾后验收，带打过勾的检查项 | 不通过（写理由） | — |
| 确认诊断 | 对 / 位置部分对 / 不对 / 误报（照产品现有的四个选项） | 重新诊断 | — |
| 诊断被否、没有诊断 | 重新诊断 | 忽略 | — |
| 诊断已确认、方案被退回、执行失败 | 生成方案；执行失败另有「重新诊断」 | 忽略 | 按这条意见重做 |
| 批准了没开始 | 按住重试执行 | 撤回批准 / 撤销变更（写理由） | — |
| 等收尾 | 标记已解决 | — | 补做检查 |
| 变更草稿 | 开始审核 | 撤销（写理由） | — |
| 审核要澄清 | 回答并提交（后端收一段话，界面按问题分格填、合成一段发出） | — | — |

- **和设计稿不一样、照实做的地方**
  1. **没有「要求修改」。** 后端存了退回的理由，但出方案的 agent 读不到。`R` 叫「退回方案」：退回后这件事以「方案被退回」回到队列，再点「生成方案」。界面不写「agent 会按你的话重做」。
  2. **没有 5 秒撤回。** 后端一批准就开始执行，决定立即生效。保留「按住」和「必须写理由」。
  3. **「对」之后不自动出方案**，要再按一次「生成方案」（后端现在就是这样）。
  4. **忽略的理由和副作用要说实话。** 现有接口不保存忽略的理由，而且忽略会让检测 agent 记下「这类情况是误报」。新界面先把理由作为备注写进时间线再忽略，并在确认处写明第二点。
  5. **批准按钮上的字跟着服务端走**：执行器关着时批准只是批准，不写「并执行」（用现有的 `lib/approval`）。
  6. **交给 agent 之后，后端没有「已经开始」的记录**：点了「重新诊断」「生成方案」，这件事在后端看来仍然「在等你」，直到 agent 交出结果；刷新页面就看不出点过，再点会起第二个 agent。新界面在本浏览器里记一笔（「你 3 分钟前在这个浏览器里点了生成方案」），按会变化的事实对账，变了就清掉；期间不让重复点。这只是这个浏览器的记录，照实标明。
  7. **只读账户的队列按设计就是空的**：写「只读账户，没有事会派给你」，不写「全部处理完了」。
  8. 证据速览只显示后端存下的摘要和出处（原始输出没有存）。

### 5. 经过页
六步的状态用现有的 `issuePhases` / `changePhases` 算；时间线、备注（追加）、诊断、方案的每一步、每次执行、重新打开已忽略的问题，都是已有接口。后端状态的原名照实显示。

### 6. 现场（第一版按状态拼，没有实时步骤）
- 后端今天没有「现在哪些 agent 在跑」的接口，没有实时推送，执行器的步骤结果要到结束才写。
- 只列**能核实正在进行**的：`investigating` 的问题、`fix_executing` 和已批准且执行在途的问题、`under_review` / `executing` 的变更、正在运行的定时任务、正在构建的关系图，加上做法 4 第 6 条那种「你刚交出去的」。每条写明依据和已经多久——卡住的会很显眼。步骤取时间线，轮询刷新。
- 不显示插话、暂停、叫停。页面顶上一句话写明「这里是按状态拼的」。取数失败时保留上一次的内容并标明时间。
- 这份「在做的事」的清单 N2 就先做出来，放在待决右边一栏（否则批准之后那件事只是从队列里消失）；N4 才是完整的现场页。

### 7. 全景（平面 + 3D）
- 数据：`GET /api/galaxy/graph`（节点带健康四值和「已不见」，关系分规则 / 模型推断）+ `GET /api/galaxy/status`。这份图是某次构建的快照，「数据核对」里写明构建时间，以及它和当前资源清单差多少。
- **真实数据的形状和示例不同，照实处理**：节点有账户、分组、资源三种，没有区域也没有坐标；`contains` 有多个上级的情况。做法：账户是区域的标签，分组是一种筛选，资源按「包含」关系成树、每个资源只取一个确定的上级来定位；同一份数据每次算出同一个位置，不跑力导向模拟。「只看周围」和「找路」不穿过账户和分组这类汇聚点（否则任意两个资源都「两步相连」）。
- **方向有四种**（顺着、逆着、双向、无）：后端的方向表（`graph/relations.py`，11 行）在前端照抄一份，配共用清单 `tests/fixtures/relation_propagation.json`，两边的测试各自对它——不改接口。流动的点只在方向已知的关系上画。
- **一份结果、两种画法、一块核对**：照原型搬——`scene()` 只算一次，平面（Canvas）和 3D 都只负责画，面板上的数字从同一份里取；「数据核对」把画布上实际画的和数据逐项比。接上真数据后，核对是绿的才算过。
- 「在等你的 N 件事里，几件在图上」：用队列和图对出来。
- **3D**：npm 依赖 `3d-force-graph` 和 `three`（都是 MIT），单独分包，第一次切到 3D 才下载；引擎版本钉死（核对要读它内部的对象）。**先在真实的 1,966 个节点上量帧率**；低于 30 帧就不用这个引擎的默认画法，改成合批绘制。这是这一轮**唯一新增的前端依赖**。
- 不显示时间回放（后端没有资源状态的历史）。旧的 Galaxy 页不动。
- 设计里「待决」背后的星图背景，要到 N5 才有；之前是纯色背景。

### 8. 一处只读的后端补充（建议做；可以划掉）
- **方案的每一步带上「会改动 / 只读 / 分不了类 / 禁止」**。批准简报上「这是代码分的类」是信任的核心；分类函数后端已有（`services/change_steps.command_tier`），只是没有返回。做法：方案响应加一个和步骤并列的只读列表 `step_tiers`，不进内容哈希，带后端测试。不做的话，这个标注先不显示。

六个面（项目规矩，逐行写明）：

| 面 | 这一轮 |
|---|---|
| CLI | 非目标（不变） |
| Web API | 做：`step_tiers` 一个只读字段（可划掉）；其余不变 |
| Web UI | 做：`/app/new` 整套；旧界面只加入口 |
| Agent 工具 | 非目标（不变） |
| 定时任务 | 非目标（不变） |
| 通知 | 非目标：通知里的链接仍指向旧页面，等新界面成为默认时再改 |

## 阶段

每个阶段开工前把这一段展开成细的任务清单（存进 `docs/superpowers/plans/`）；然后先写失败的测试 → 实现 → 自查 → 本地提交 → **在独立的 :8001 实例上给你预览** → 你验收后才进下一个、才推送。

| 阶段 | 做什么 | 预览时你看到的 |
|---|---|---|
| **N0 入口和骨架** | 分支；路由和外壳；样式、文字、键盘的底座；旧界面里的入口；**真实的队列**（分页、排序、筛选、数量）；选中一件事显示通用简报；顺手对副本库做一次只读统计（关系图的形状），给 N5 用 | 从旧界面点进来，看到真实的「在等我」，`J` / `K` 移动，每件事有通用简报和去旧页面的链接 |
| **N1 三种最常用的简报** | 批准（问题）、验收、确认诊断：真数据、真决定；按住批准的安全处理；证据速览；影响范围的数字；`step_tiers` | 在新界面里读简报并做决定（预览实例上执行器是关的，批准不会真的执行） |
| **N2 其余简报、变更单、在做的事** | 另外 8 种简报；变更单；共用清单覆盖全部 17 种组合；「交出去的」本地记录；右边一栏「agent 现在在做」 | 每一种情形都有自己的一页；做完决定能看到它去了哪 |
| **N3 经过页** | 问题和变更的六步、时间线、备注、方案、每次执行；从哪来回哪去；地址可直达 | 任意一件事按 `Enter` 看来龙去脉 |
| **N4 现场页** | 把 N2 的清单做成完整的一页；每条的步骤；断线时的样子 | 现在谁在做什么、做了多久 |

## 风险和取舍

| 风险 | 应对 |
|---|---|
| 队列有 140 件，不是「眼前的几个」 | 严重度优先 + 分组筛选 + 分页。真正变少要靠批量处理，这一轮不做 |
| 没有撤回窗口，手滑的代价变大 | 批准必须按住且只认按下时的目标；退回、忽略、拒绝、撤回都必须写理由；忽略可以重新打开 |
| 「交出去之后」后端不知道 | 本浏览器记一笔并照实标明；换一台电脑看不到——这是缺口 1 要解决的 |
| 现场第一版没有实时步骤，会显得单薄 | 照实标注；你可以在 N3 之后决定先补后端缺口 1 再做现场页 |
| 原型的样式进 Tailwind 工程互相影响 | 选择器全部加前缀并有测试；N0 逐屏对照；进出新界面前后对比旧页面截图 |
| 3D 多一个较大的依赖，且引擎默认画法可能不够快 | 单独分包、按需下载；先量再定画法 |
| 真实的图和示例数据形状不同 | N0 先做只读统计；N5 先做布局和核对，再做交互 |
| 检查时误触真实动作 | 预览实例关掉执行器；调用模型的接口限量；`agent-memory/` 还原 |
