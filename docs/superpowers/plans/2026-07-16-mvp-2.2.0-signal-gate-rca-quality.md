# MVP-2.2.0 Implementation Plan — Signal Gate + RCA Quality Quintet + Agent Cleanup

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** All issue-creating events flow through one deterministic-first Signal Gate (dedupe/noise/promote with audit trail), and RCA gains thinking + evidence verification + critic review + confidence gating + incident memory + human feedback.

**Architecture:** New `services/signal_gate.py` becomes the single choke-point for all three HealthIssue creation paths (agent tool / webhook / REST). The existing `alert_events` table is generalized into the Signal ledger (every event = one row with disposition + reason + evidence). RCA's side-effects (auto-SRE, notify) move out of `save_rca_result` into a post-run pipeline inside `rca_agent` (evidence check → critic → confidence gate), so every RCA entry point is covered.

**Tech Stack:** Python 3.12, SQLAlchemy (inline ensure-column migrations in models.py), Strands SDK 1.45 (BedrockModel `additional_request_fields`, `Agent.__call__(limits=)`), FastAPI, React + TanStack Query, pytest.

**Spec:** `docs/superpowers/specs/2026-07-10-mvp-2.2.0-signal-gate-rca-quality-design.md`

## Global Constraints

- All new config values go in `config.py` (schema only) + `config/settings.yaml` (defaults) — never hardcode (house rule).
- Never use bare `boto3.Session()` — L2 gate LLM calls use `get_bedrock_boto_session()` (Bedrock control plane exception).
- LLM may only decide **merge vs new** (never noise); uncertainty → promote (fail-open). Deterministic rules only may declare noise.
- Signals ledger: every inbound event leaves a row with `disposition` + `disposition_reason` + `gate_evidence`.
- Legacy return-string formats of `create_health_issue` ("Created HealthIssue #N…", "Deduplicated: …", "Suppressed: …") must be preserved (agent prompts parse them).
- `AlertProcessResult.action` contract (`created|deduplicated|noise|error`) preserved for web/app.py webhook callers.
- Commit locally after each green task; **never push** (owner pushes after E2E + confirmation).
- Existing tests must stay green: `python -m pytest tests/ -x -q` at each commit point.

**Interfaces (Produces):**
```python
@dataclass
class SignalInput:
    source: str; title: str; description: str; severity: str
    resource_id: str = ""; account_id: str = ""; provider: str = "aws"
    issue_type: str = "other"; upstream_key: str = ""; kind: str = "alert"  # alert|detection|resolution|manual
    metric_data: dict = field(default_factory=dict); related_changes: list = field(default_factory=list)
    alarm_name: str = ""; trace_id: Optional[str] = None; im_origin: Optional[dict] = None
    auto_rca: bool = True; detected_by: str = "detect_agent"

@dataclass
class GateDecision:
    disposition: str          # promoted | merged | noise
    reason: str               # exact_fingerprint | resolved_cooldown | flapping | excluded_pattern | resource_type_merge | llm_merge | new_issue | resolution_update | manual_override
    issue_id: Optional[int]   # created (promoted) or target (merged); None for noise
    signal_id: Optional[int]
    created: bool             # True only when a new HealthIssue row was inserted

def compute_fingerprint_v2(account_id, provider, resource_id, issue_type, upstream_key, title="") -> str
def classify_issue_type(title: str, source: str = "", namespace: str = "", metric: str = "", alertname: str = "") -> str
ISSUE_TYPES: tuple[str, ...]   # 16 types from spec §2.2
def process_signal(sig: SignalInput) -> GateDecision
def merge_into_issue(session, existing, *, source, title, description, severity, fingerprint, metric_data, related_changes) -> None   # unified merge (replaces the two copies)
RESOURCE_DEDUP_STATUSES  # moved here; metadata_tools re-imports
```
Key behavior (locked decisions):
- fingerprint_v2 = sha256(`{account_id}|{provider}|{resource_norm}|{issue_type}|{upstream_key}`); when `resource_id` empty/`unknown` AND no `upstream_key`, last component falls back to digit-stripped lowercase title (today's behavior as floor).
- `process_signal` is wrapped in a module `threading.Lock` (single-process serialization).
- L1 order (short-circuit): ① exclude patterns (title regex, `settings.issue_exclude_patterns`) → noise/excluded_pattern; ② `kind=="resolution"` → find active-or-recent issue by fingerprint, append resolution marker to merged_alerts (never bump severity), disposition merged/resolution_update (or noise/orphan_resolution when no match) — feeds flap window, never creates an issue; ③ fingerprint exact match on `_ACTIVE_ISSUE_STATUSES` → merged/exact_fingerprint (occurrence+1, last_seen, severity escalate, merged_alerts snapshot; description/metric refresh only in open/investigating); ④ resolved cooldown (`dedup_resolved_cooldown_minutes`) → merged/resolved_cooldown; ⑤ flapping — count AlertEvent rows with same fingerprint in `noise_flap_window_minutes`; if ≥ `noise_flap_threshold` → noise/flapping; ⑥ same `resource_id` AND same `issue_type` in `RESOURCE_DEDUP_STATUSES` → merged/resource_type_merge.
- L2 gray-zone trigger (any): same resource_id different type/wording active issue; same account+issue_type active issue in flap window; token-Jaccard(title) ≥ 0.5 vs an active issue. Call cheap-tier `converse` (temp=0, JSON `{"action":"merge|new","target_issue_id":int,"confidence":float,"reason":str}`), candidates ≤ `signal_gate_candidate_cap`. Only `merge` with confidence ≥ `signal_gate_confidence_min` and a valid candidate id merges (merged/llm_merge, full LLM I/O into gate_evidence); anything else → promote. LLM can NEVER output noise. Disabled/エラー → promote.
- Promote: create HealthIssue (moves the creation block from `_create_health_issue_impl`: account/provider inventory resolve, im_origin/trace_id inject, fingerprint=v2, issue_type, occurrence=1, first/last_seen) + `issue_created` event + `trigger_auto_rca` (if `sig.auto_rca`) + `notify_issue_created`. Merged/noise are silent (no notify, no RCA) + `signal_gated` PipelineEvent on target issue when merged.
- EVERY call writes one AlertEvent row (the Signal) with kind/fingerprint/resource/account/issue_type/disposition/reason/gate_evidence/health_issue_id/trace_id; status="processed" (promoted/merged) or "ignored" (noise).
- Retention: module-global last-prune date; once per process-day DELETE AlertEvent older than `signal_retention_days`.
- `signal_gate_enabled=false` → skip L1②⑤⑥/L2, only run legacy-equivalent steps (①③④ preserve old behavior) — rollback valve.
