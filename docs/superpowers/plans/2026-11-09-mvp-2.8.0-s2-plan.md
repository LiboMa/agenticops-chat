# MVP-2.8.0 S2 实施计划：待办工作台、侧栏、问题队列视图、执行结果前置、验收核对

> **执行方式：** 必须用 superpowers:executing-plans 在本会话内联执行。每一步先写测试，看它失败，再实现。页面接线这类代码在 node 环境的 vitest 里没法渲染，就用真实应用上的 E2E 复现来充当会失败的测试。

**目标：** 实现 spec 的 S2，即样本第 5、7 项与审阅 R07、R08、R15：
- 侧栏重排；
- `/app/inbox` 待办工作台；
- Cases 的四个快捷视图，以及每行的等待信息；
- 问题页、计划页、变更页的首屏：执行结果和下一步排在长计划之前；
- 带核对项的验收对话框，勾选的核对项记到服务端。

**架构：**
- 后端：把「谁在等、从什么时候开始等」抽成一个共用函数，attention、问题列表、问题详情、变更详情都用它。
- attention 只做加法：多给几个字段，多接几个筛选参数，多返回分组数量。
- 问题列表改成 `{items, total}`，加 `view` 参数，另开一个计数接口。
- 两条验收路径各加一个可选参数 `confirmed_checks`。
- 前端：一个新页面、一个首屏组件，再加几个纯函数（工作台的行模型、执行摘要、验收核对项）。

**技术栈：** FastAPI + SQLAlchemy；React 18 + TanStack Query v5 + Radix（已安装）；vitest（node 环境）；Playwright。不加依赖。

**Spec：** `docs/superpowers/specs/2026-11-08-mvp-2.8.0-workspace-redesign-design.md` 的 S2 一节、「全局约束」、「我的判断」。
**设计样本：** `reports/frontend-review-2026-11-07/design-preview/images/desktop-workbench.png`、`desktop-acceptance.png`、`desktop-inbox.png`、`mobile-issue.png`。
