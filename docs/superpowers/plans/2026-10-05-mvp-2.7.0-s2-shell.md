## S2 详细计划

> 依据：设计包 `refinement.css` / `refinement.js` 的外壳规格、`target-openapi.json` 的 `UiBootstrap` / `UserPreferences` 契约、三份代码探查（行号以 `MVP-2.7.0` 当前 HEAD 为准，实施时以 grep 为准）。

### 现状（已复核）

- **路由**：`App.tsx` 的 `/app` 首页是 Dashboard；**没有 catch-all**（`/app/foo` 白屏）；`RequireAuth` 只查 token、跳登录时丢掉原 URL；`Login.tsx:19` 永远进 `/app`；`api/client.ts:67-73` 401 时整页跳 `/app/login`，也丢原 URL，且把登录接口自己的 401「Invalid credentials」显示成「Session expired」。后端 `/anomalies`、`/anomaly/{id}` 重定向到前端不存在的路由（白屏，`web/app.py:443-466`）。
- **外壳**：`IconSidebar` 52/200px 可折叠、`NavItems` 一维列表 + 拖拽排序（`aiops-nav-order`）+ 悬停预览卡（`NavPreviewCard`）、`MinimalTopBar` 36px 只有页名 / 邮箱 / Logout / CN-EN / 主题；**完全没有响应式**；`Chat.tsx:150`、`Galaxy.tsx:318` 用 `h-[calc(100vh-2.25rem)] -m-6` 绑死了顶栏 36px 和 `main` 的 `p-6`。
- **主题 / 字体**：浅色 token 已基本就是设计的蓝白（primary `221 83% 53%` = #2563EB、正文 #0F172A、次级 #64748B、分隔线 #E2E8F0），差在页面底色（应为 #F8FAFC）、蓝色焦点环、标题字号；**深色主题的 primary 是绿色**；字体从 Google Fonts 加载（客户离线环境拿不到），`index.html` 还多拉了从没用过的 Inter；`useTheme` 是普通 hook，只有顶栏调用，登录页没有主题、字号设置没有任何界面能改；`<html lang>` 永远是 en。
- **身份**：认证关闭时 `current_actor` 永远是 `web:anonymous`，但 UI 总是登录的；能在两种模式下认出登录用户的只有「自己校验 Bearer 头」（`/api/users/me`、`deps.require_authenticated_user` 就这么做）。
- **S1 遗漏**：`GET /api/settings` 是 `async def`，缓存空时同步调 Bedrock 列模型（`model_service._fetch_bedrock_models`）——违反 S1「事件循环上无阻塞」。CORS 没放行 PATCH / `If-Match`、没暴露 `ETag`。

### 要点与决定

1. **配色与字体**（`index.css`、`tailwind.config.ts`、`index.html`）
   - 浅色：页面底色 #F8FAFC，卡片 / 侧栏 / 顶栏白；新增 `--selected`（#EFF6FF）与 `--primary-hover`（#1D4ED8）；全局 `:focus-visible` 蓝色 2px 焦点环（设计稿遗留的青色焦点环不用）。
   - 深色：**保持现状（主色仍为绿色，主人 10-05 决定）**；深色仍是用户选项，首次进入一律浅色（不再跟随系统深色）。
   - Outfit **本地打包**：新增依赖 `@fontsource/outfit`（400/500/600/700），删除 Google Fonts `@import` 和 `index.html` 的 Inter / JetBrains Mono 链接；中文回退 `"PingFang SC","Microsoft YaHei"`；等宽改系统栈 `ui-monospace, SFMono-Regular, Menlo, monospace`。验收标准：构建产物与运行时**零外部字体请求**。
   - `useTheme` 改为应用级 `ThemeProvider`（`main.tsx`），登录页也生效；字号（小/中/大 = 13/15/17px）和主题放进顶栏头像菜单；`<html lang>` 随语言切换。
2. **侧栏**（新 `components/layout/Sidebar.tsx`，替换 `IconSidebar` + `NavItems` + `NavPreviewCard`）
   - 宽 200px（≤1100px 时 166px），白底；品牌块（logo + AgenticOps，点它去 Chat）。
   - 三组：**日常工作**（不可折叠）Chat、Cases（`/app/issues`，有未结事件时显示红点；准确计数在 S4）、Reports；**运维工具**（可折叠）Changes、Audit、Resources、Schedules；**管理**（可折叠）运行总览（`/app/overview`）、Agent 指标、Skills、Galaxy、Security、Settings。两组默认收起，当前页所在组自动展开，展开状态存偏好 `nav_groups_open`。
   - S2 不改名「Plans & changes」：枢纽要到 S3 才有修复方案列表，现在叫它会名不副实；S3 把 Changes + Audit 合成「Plans & changes」。
   - 选中态：`#EFF6FF` 底 + 蓝字 + 600 字重 + `aria-current="page"`，无左边框（按设计稿）。
   - **保留组内拖拽排序**，旧的一维 `aiops-nav-order` 按组投影迁移到 `aiops-nav-order-v2`，相对顺序不变，不清空。
   - 去掉 52px 图标折叠态和悬停预览卡（设计稿里都没有；主人 10-05 确认去掉）。
   - 底部「首页与语言」按钮 → 对话框：默认入口（继续上次工作 / 对话 / 事件 / 报告）+ 保存；下面一行显示版本（来自 bootstrap）。
   - ≤800px：侧栏隐藏，顶栏出现原生 `<select>` 导航（每组一个 optgroup），与设计稿一致。

   - 高 64px（≤800px 56px），白底 + 底分隔线；用 CSS 变量 `--topbar-h` 让 `Chat` / `Galaxy` 的整屏布局不再写死高度。
   - 左：面包屑 `AgenticOps / {分区}`，详情页再加对象编号（`I#5`、`C#3`、`R#7`）；`document.title = AgenticOps · {分区}`。
   - 右：搜索按钮（打开现有 Command Palette，显示 ⌘K；≤1100px 只剩图标，≤600px 隐藏）、语言分段切换 `中文 | English`（`aria-pressed`）、头像菜单（姓名首字母；菜单：邮箱、主题、字号、退出登录）。

4. **路由**（`App.tsx`）
   - `/app` → `HomeResolver`：固定首页（对话 / 事件 / 报告）> 继续上次工作（白名单路由；对象路由先探测一次对象接口，404 / 403 时回到它的列表）> `/app/chat`。只在 `/app` 生效，显式路径从不被偏好覆盖。
   - 新增 `/app/overview`（原 Dashboard）；新增 catch-all → 「页面不存在」+ 回到对话的链接。
   - 登录回跳：`RequireAuth` 与 401 都带 `?next=`；`Login` 只接受白名单内的站内路径（以 `/app/` 开头、不是 `/app/login`、不含 `//` 与协议），否则进 `/app`。登录接口自身的 401 显示服务端原因（不再显示「Session expired」）。
   - 上次位置：外壳在路由变化时记录**白名单路径**（不含查询串、不含任何 token），本地立即写、服务端去抖写（偏好 `last_route`）。
   - 旧链接：保留 `/app/plans?tab=`、`/app/issues?view=`、`/app/issues/:id?tab=` 现有映射；后端 `/anomalies` → `/app/issues`、`/anomaly/{id}` → `/app/issues/{id}`。
5. **偏好与 bootstrap**（新 `web/routers/ui.py` + 新表 `user_preferences`）
   - 新表 `user_preferences(user_id PK, revision, data JSON, updated_at)`：`create_all` 自动建表，不需要 ALTER。
   - 身份：直接用 `deps.require_authenticated_user(admin=False)`（中间件放好的 `request.state.user`，或自行校验 Bearer：会话 token / API key），两种认证模式都成立；没有有效 token → 401。
   - `GET /api/users/me/preferences` → `{revision, locale, home, last_route, nav_groups_open}`，默认 `revision=1, home=resume, last_route=null, nav_groups_open=[]`，`locale` 首次取浏览器本地值（见修订 2），响应头带 `ETag`，revision 也在响应体里（前端 `apiFetch` 只读响应体）。
   - `PATCH /api/users/me/preferences`：**必须**带 `If-Match: <revision>`。缺少 → 428；不符 → 412 并返回当前偏好（前端取回后重放一次本次改动）；成功 → revision+1，返回新偏好和新 `ETag`。请求体字段全部可选、至少一个、禁止多余字段（422）；`home` / `locale` / `nav_groups_open` 是枚举；`last_route` 走与前端相同的白名单规则（≤1000 字符、`/app/` 开头、无查询串和协议）。
   - `GET /api/ui/bootstrap`（按契约 `workspace-ui-1`）：`contract_version`、`deployment_id`（随机 id，存数据库，见修订 14）、`user`（id / email / name / is_admin）、`auth_enabled`、`locale`、`features`（`change_management` 取设置；`revision_guards` / `attention` / `context_chat` / `content_rendering` / `report_export` / `chat_replay` 目前都是 `false`，到对应阶段再打开）、`upload_policy`（按 `chat/file_reader` 的真实分流规则导出，见修订 9）、`version`、`preferences`。**不含任何连接器或密钥字段**（测试逐个断言）。
   - 前端：`useBootstrap` + `usePreferences`（乐观更新、带 If-Match、412 时取回后重放一次）；语言、首页、展开组、上次位置都经它读写；登录后以服务端偏好为准，本地 localStorage 只作首屏前的缓存。
6. **顺手修的 S1 遗漏**：`GET /api/settings` 改为普通 `def`（与 S1 的处理器同一做法），并补进 `tests/test_single_process.py` 的清单；CORS 放行 PATCH 与 `If-Match`、暴露 `ETag`。
7. **中英文**：外壳里所有文案（分组、菜单、对话框、搜索、语言、404、面包屑、登录页）都走 locale；顺手删掉外壳里写死的英文（`Logout`、主题提示、Command Palette 文案）。

### 审查后的修订（Plan 子代理对抗审查：4 阻塞 / 10 重要 / 7 次要，全部吸收；与上文冲突时以本节为准）

1. **侧栏排序迁移**：`usePersistedState` 首次挂载就把默认顺序写进 `aiops-nav-order`，所以「存了」≠「改过」。规则：v1 存值按 v1 默认顺序归一后**等于 v1 默认** → 直接用 v2 默认分组；否则按组投影保留相对顺序。改名表加 `dashboard → overview`。`__tests__/navOrder.test.ts` 改为测 `lib/navGroups.ts`（不再从 `NavItems.tsx` 导入）。分组 id 用契约的 `tools` / `administration`。
2. **语言**：服务端偏好 `revision == 1`（从未保存）时**保留本地语言**并 PATCH 一次；「应用服务端语言」不触发 PATCH，只有用户点切换才写。默认值不再把英文用户翻成中文。`LocaleProvider` 在 QueryClient 外，用一个桥接组件同步。
3. **上次位置写入**：每个标签页的偏好 PATCH 串行排队；只改 `last_route` 的写入用 `If-Match: *`（服务端按字段合并，覆盖不了 `home`）；最多 30 秒一次、值变了才写，`pagehide` 时用 `fetch(keepalive)` 补写；自动展开当前组**不写**偏好。
4. **首页解析与共享浏览器**：`HomeResolver` 等 bootstrap 返回再跳（转圈），失败或 3 秒超时 → `/app/chat`；只在有 token 时请求 bootstrap。本地缓存（偏好、上次位置、Chat 的 `aiops-last-session-id`）**按 user_id 分键**，登录时发现换了用户就清掉。
5. **登录回跳**：保留查询串和 hash（Issue 的阶段在 hash 里）。用 `new URL(next, location.origin)` 校验：同源、路径是 `/app` 或以 `/app/` 开头、不是 `/app/login`；只用 `navigate()`。401 处理器用 pathname + search + hash 生成 `next`。登录失败显示 locale 文案，服务端原因作补充。
6. **If-Match 形式**：`ETag: "3"`；服务端接受 `"3"`、`W/"3"`、`3`、`*`；412 返回 `UiError {detail, code}`，前端重新 GET 后重放；缺 If-Match 返回 428（记为对契约的补充）。
7. **原子更新**：`UPDATE … WHERE user_id=? AND revision=?`，0 行 → 412；首次插入撞唯一键 → 412。模型放在 `auth/models.py`（`init_db` 会导入，`create_all` 才建得出表）。
8. **features 如实**：`revision_guards = false`（契约里它指审批写入的 If-Match / 412 / 428，2.6.1 只有请求体里的 content_hash + 409），S3/S4 实现后再改 true。
9. **上传策略**：按 `file_reader` 真实的分流规则导出（图片 = `IMAGE_FORMAT_MAP`，文档 = `DOCUMENT_FORMAT_MAP`，文本 = `TEXT_EXTENSIONS` 减去文档类）；`MAX_UPLOAD_FILES` 移到模块常量。S2 不改 Chat，前端 `lib/attachments.ts` 的那份暂不动（S5 再统一）。bootstrap 测试断言**顶层字段集合完全等于**契约集合（含 `contract_version`、`user_id`）。
10. **S1 遗漏扩大**：除 `GET /api/settings` 外，`PATCH /api/settings` 和 `PATCH /api/chat/sessions/{id}` 里的 `_allowed_model_ids()` 也可能在事件循环上列 Bedrock 模型 → `asyncio.to_thread`。
11. **手机端**：设计稿在 ≤800px 隐藏头像和侧栏，会让退出、主题、字号、首页设置在手机上无处可点 → 手机端保留头像菜单，并把「首页与语言」放进它。原生 `<select>` 导航对不在列表里的路由显示占位项，详情页映射到所属入口。
12. **深色模式**：主人决定深色保持绿色主色，S2 不改深色 token 和徽章颜色（已知：7 处 `blue-* dark:green-*` 的「执行中」徽章在深色下偏绿，维持现状）。仍在 `index.html` 的 `<head>` 加一小段脚本，在首次绘制前设置主题类、字号和 `lang`（`zh-CN` / `en`），消除闪烁。
13. **Cases 徽标**：`open_anomalies` 只数 `status=='open'`、且含安全发现，而列表默认只看运维事件、包含其它未结状态——数字会对不上。S2 保持红点，S4 做列表时再给准确计数。
14. **deployment_id**：存数据库（`init_db` 时确保一行），不放 `data_dir` 文件（EKS 的 emptyDir 每次重启都会丢）。
15. **对象探测**：只探测事件 / 变更 / 会话 / 报告四类；用 `queryClient.fetchQuery`（与页面同一个 key 和函数、`retry:false`、`staleTime:30s`），不重复请求；404 / 403 时清掉 `last_route`，回到对应列表并提示「上次打开的对象已不存在或无权访问」（**不显示对象标题**）。
16. **白名单单一来源**：路由白名单写成一个 JSON 夹具，Python 和 TS 的测试都读它，保证两边一致。
17. **命名**：`R#` 已经表示资源，报告详情面包屑用「报告 #7」。
18. **可访问性**：可折叠组用 `<details>/<summary>` 或 `button[aria-expanded]`；非 Mac 显示 `Ctrl K`；去掉 `index.css` 里 `input:focus{outline:none}` 对新焦点环的覆盖；拖拽排序没有键盘路径，记为已知缺口。
19. **构建**：新增依赖同提交更新 `package-lock.json`（Dockerfile 用 `npm ci`）。已跟踪的 `dist/` 开发期不提交（与 2.6.1 一致），发布时（S7）统一处理。
20. **403**：探测到 403 与 404 同样处理（回列表 + 提示），并纳入验收。
21. **删减**：开机不单独 GET 偏好（直接用 bootstrap 里的）；侧栏底部不显示时区（契约里没有）；不写 `deps.require_user` 包装，直接用 `require_authenticated_user(admin=False)`；CLI 启动横幅里的「Dashboard: …/app/」改成「Web: …/app/」（`cli/main.py:1443,4872`），可达面 CLI 一行由「非目标」改为「做（文案）」。

### S2 交给主人的验收清单（手动）

1. **首访进对话**：清空浏览器存储后登录，进入 `/app`，落在对话。
2. **恢复上次工作**：打开某个事件，再访问 `/app`，回到这个事件；把它删除后再访问 `/app`，回到事件列表，并提示「上次打开的对象已不存在或无权访问」（不显示标题）。同一浏览器换另一个账号登录，不会恢复到上一个人的位置或会话。
3. **固定首页**：「首页与语言」里选「报告」，访问 `/app` 进入报告；直接打开 `/app/issues/1` 仍是这个事件（深链优先）。换一个浏览器登录同一账号，首页偏好相同。
4. **登录回跳**：退出后打开 `/app/changes/1` → 登录 → 回到 `/app/changes/1`；`/app/login?next=https://evil.example` 登录后进 `/app`。
5. **旧链接**：`/app/plans?tab=audit`、`/app/issues?view=resources`、`/anomalies`、`/app/不存在` 各自落到正确页面或 404 页。
6. **侧栏**：三组、两组可折叠并记住状态；从没拖过的用户看到新的默认分组，拖过的用户组内相对顺序保留；Cases 有未结事件时显示红点（准确计数在 S4）。
7. **外观**：蓝白；深色模式照旧可用（主色仍为绿色）；字号可调；中英切换覆盖外壳全部文案；Network 面板里没有任何外部字体请求。
8. **窄屏**：768px 侧栏变窄、搜索只剩图标；390px 用顶栏下拉导航，头像菜单里能退出、改主题 / 字号 / 首页，没有横向滚动。
9. **多标签页**：两个标签页各改一次首页偏好，最后一次生效、不报错；来回切页面不会产生大量偏好请求（Network 面板里 30 秒内最多一次）。
