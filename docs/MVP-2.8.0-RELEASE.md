### 接口

- `GET /api/ui/attention`：
  - 每项新增 `severity`（问题）、`risk_level`（变更）、`resource {ref, name, type, resource_id}`（只在资源和问题同一账号时给）、`region`、`waiting_on`；
  - 新参数 `reason`（逗号列表，不认识的值返回 422）、`q`（≤ 200 字）、`sort=waiting_longest|newest|severity`；
  - 返回体新增 `counts {reason: n}`：在账户范围和搜索之后、`reason` 过滤之前统计。
- `GET /api/health-issues` 返回 `{items, total}`（以前是裸数组），每行加 `waiting_on`、`waiting_since`；新参数 `view=all|mine|failed|long_wait`。`GET /api/health-issues/view-counts?scope&account_id` 返回四个视图的数量，和带同一 `view` 的列表 `total` 一致。详情接口也带两个等待字段。
- `GET /api/changes/{id}` 加 `waiting_on`、`waiting_since`。
- `POST /api/fix-executions/{id}/accept` 和 `POST /api/changes/{id}/resolve-review` 的请求体加可选的 `confirmed_checks`：最多 50 个 `pc-n`，每个都必须是那次执行自己计划里声明的检查，否则 422，什么都不写；不传时和以前一样（CLI `/accept` 不变）。accept 路由改为普通 `def`。
- 「谁在等、从什么时候开始等」只有一份定义：`services/attention.issue_waits` / `change_waits`，attention、问题列表、问题详情、变更详情都用它。
- 新配置 `attention_long_wait_hours`（`config/settings.yaml`，默认 24，≥ 1）。

## S1 状态可信 + 可访问性 + 定时任务的真实运行状态（2026-11-09）

计划：`docs/superpowers/plans/2026-11-08-mvp-2.8.0-s1-plan.md`。E2E：[`MVP-2.8.0-E2E-REPORT.md`](MVP-2.8.0-E2E-REPORT.md)。

### 共用件（后面七个阶段都用）

- **四种数据状态**：`lib/queryState.queryView` 和 `components/ui/QueryState`。
  - 状态分为加载中、失败（带重试）、空、成功。
  - 「空」只在请求成功、而且确实返回空集合时出现。
  - 刷新失败、手里还有上次的数据时，照常显示旧数据，并标出「刷新失败，正在显示上次成功获取的数据 · 数据截至 HH:MM UTC」，附「重新获取」。
  - 每个模块各套一层，一个失败不会把别的藏起来。
- **状态文字**：`components/ui/StatusText`。状态永远写成文字（一个小圆点 + 文字），颜色只起辅助作用。
- **开关**：`components/ui/Switch`，基于 Radix。
  - `role="switch"` + `aria-checked`。
  - 名称和说明通过 `aria-labelledby` / `aria-describedby` 关联。
  - 可以用 Space / Enter 切换，焦点环可见。
  - 点击区 44 px。
- **浅色主题**改用样本色值：
  - 页面 `#F6F8FC`、正文 `#17243C`、次要文字 `#596B86`、主色 `#2863EB`；
  - 三个状态色：绿 `#167351`、琥珀 `#915B0A`、红 `#B42318`；
  - 暗色主题不变（主人 2.7.0 S2 的决定）。

### 整个分支评审之后（2026-11-09）

评审结果：没有 Critical；4 个 Important 加 2 个由 Minor 重新定级上来的，都已修复；另有 9 个 Minor 记录在案，留到后面处理。

- 存下来还是「运行中」的步骤，现在写「结果未知」。
- 每周 cron 不再给出星期几的说法。
- 任务详情、发送记录、Schedules 列表、Reports 列表也都用上了四种数据状态。
- 表单里的「启用」开关有了正确的名称。
- 窄屏下主按钮单独一行。
- cron 预览显示 UTC。
- 执行记录接口改成普通 `def`。
- 输入法选词时按 Enter 不再打开搜索结果。

**需要主人定：调度器的星期几差一天。** `scheduler.CronParser` 用 Python 的 `weekday()`（周一 = 0）去比对 cron 的星期几（周日 = 0）。所以写着 `0 0 * * 1`（周一）的任务实际在周二运行，`cost-expense-monthly-report` 就是这样。改正调度器后，现有的每周任务会挪到它们写着的那一天。
