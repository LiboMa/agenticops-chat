这条分支只做设计：一份可点击的原型，加一份别人能照着实现的设计规范。**不改 `src/` 下的任何产品代码。**

- 计划：`docs/superpowers/plans/2026-11-11-new-ui-face-design-plan.md`
- 规范（D8 定稿）：`docs/superpowers/specs/2026-11-11-new-ui-face-design.md`

一句话：**把「900 条问题」变成「眼前的几个决定」。** 没有侧栏；四个视角（待决、现场、全景、对话）加一条指令条。

### 已经定下来的做法

- **色板**：两套主题下每一种文字色在每一种底色上都 ≥ 4.5:1（`gallery.html` 现算，`selftest.html` 断言）。正文和标签不小于 12px。
- **两种功能色**：琥珀 = 在等人；青绿 = agent 在做、代码核实。红只给「严重」，紫给「变更」。
- **不用模块**：普通 `<script>`，全局命名空间 `NF`，双击 `index.html` 在 `file://` 下就能跑（已验证）。
- **逻辑和界面分开**：`NF.createStore(seed, clock)` 不碰 DOM；每个决定都走 `store.act()`，5 秒内可撤回，新的决定会让上一个立即生效。
- **简报是注册表**：`NF.briefs[kind] = {ask, body, buttons, primary, reject, keys}`。11 种简报盖住 15 种情形（对照表见下）。
- **队列的顺序**：先按严重度，再按等待时间，和后端 `sort=severity` 的排法一致；顶部一排筛选（全部 / 批准 / 验收 / 确认 / 异常），分组和后端的 `DECISION_OF` 一致。
- **每页简报开头一句「需要你做什么」**（琥珀色的一行），然后才是内容。
- **`A` 永远是这一页的主要动作**；只有会改动基础设施的（批准并执行）才需要按住。
- **撤回之后焦点回到被撤回的那件事上。**
- **四种数据状态**统一画法；计数取不到时显示「—」，不显示 0。
- **时间一律 UTC**，并写明「UTC」。
- **原型开关**（左下角，虚线框，不属于产品）：数据状态、身份、语言、主题、重置。

D2 加的：

- **说「不」有两种**，共用一个理由框，都必须写理由，都可以 5 秒内撤回：
  - `R` **要求修改** —— agent 按你那句话重做方案，新版本回到你这里，标出和上一版差在哪几步。
  - `D` **忽略**（问题）/ **拒绝**（变更）—— 到此为止。问题记为 `dismissed`，同一来源的新信号并进它、不再提醒，之后可以在「经过」页重新打开；变更记为 `rejected`，要做得另提一张。
  - 只在「有方案或诊断要判断」的简报上有 `D`。验收必须给结论，批准了没开始的只能重试或撤回批准。
- **事情会回到你这里**：交给 agent 的事做完后以新的情形回到队列（要求修改 → 新方案待批准；批准 → 执行 → 有检查没结果就回来验收；确认诊断 → 方案待批准；变更送审 → 待批准），顶上一行说明它为什么回来。
- **「经过」页**（简报右上角，或按 `Enter`）：六步时间线（问题：发现、诊断、方案、批准、执行、验收；变更：申请、审核、方案、批准、执行、验收）。圆点五种：做完、现在、出错、停在这里、还没到。方案的每一步和每次执行可以展开。右边是事实（含后端状态的原名）和只能追加的备注。
- **状态栏说三件事**：后端状态的叫法、在等谁、账户和区域。「在等谁」按这件事此刻的实际情况算（`NF.waitsOn`），不是按状态查表 —— 同一个 `fix_planned`，方案待批准时在等你，方案被要求修改时在等 agent。
- **后端状态的对应关系对着代码核过**（`models.py` 的三张转移表、`services/work_phases.py`）：方案被退回时问题留在 `fix_planned`；撤回批准后问题回到 `root_cause_identified`，变更是 `cancelled`；`acknowledged` 等的是 agent。
- **只读账户看得到每一页，但页面上没有任何可以动手的控件**（动作按钮、打勾框、判断按钮、回答框、备注框都不画）。
- **位置（7 / 16）在简报的抬头**，动作条里只有动作：主要动作实心，其他决定凸起，「问它 / 稍后 / 忽略」是透明底。
- **屏幕上没有小于 12px 的字**（D2 把按键提示和时间刻度从 11.5 / 10px 提到了 12px）。

D3 加的：

- **「现场」是三组**：在跑、在等（等你继续、等策略、等时间）、刚做完。每一条说得出是哪个 agent、在第几步；顶栏「现场」旁边的数字是在跑的条数。「待决」右边那一栏就是这些条，点一下进现场。
- **每一步前面的记号**：◆ 代码取到的事实、◇ 模型自己的话、▸ agent 做的动作。你插的话留在记录里。
- **执行不能插话，只能叫停**：执行按你批准的那一版走（哈希绑定）。叫停要按住 `A`：正在做的这一步做完就停，然后按方案回滚。回滚完，问题带着「你叫停了执行」回到待决（和执行失败是同一页，换了说法）；变更单则到此结束（`rolled_back`，要做得另提）。最后一步已经在做时叫停来不及，照常做完并告诉你。还在 5 秒撤回期里时没有「叫停」，用撤回。
- **插话和暂停只给还在想的 agent**（诊断、出方案、审核）：`E` 插一句，`A` 暂停 / 继续。扫描和定时任务不接受插话。
- **断线不是空**：实时连接断了时，现场保留上一次的样子、标明是几点的、变灰，所有动作收起来。从没取到过才是整块的失败页。每个屏幕的失败页说的是「这不代表什么」，各说各的。
- **「全景」画的是全部资源**（示例数据 1,623 个，和「在看着的资源数」是同一个数）。每个资源有名字、类型、账户、区域。
- **健康只有四个值**：严重、有问题、有事在处理、未知。没有「健康」——没有未结问题只说明没有发现异常。另外，「已经不见了」不是健康值，是另一回事（一次完整的扫描里没有再列到它）：这样的资源不算在「在看着的」里，但也不从图上消失。
- **找资源**：`F`，按名字、类型、I# / C# 找，回车飞到第一个结果；筛选（账户、类型、只看不正常的）可以叠加，筛掉的资源变淡不消失。
- **回到过去**：拖时间条、`[` `]` 按事件前后跳、`P` 回放 24 小时、`0` 回到现在。回到过去时，哪些资源不正常按那个时刻算，资源面板也按那个时刻说；顶上一行写明「连线用的是现在的关系图」。
- **资源面板**：健康、关联的问题或变更、连着哪些资源（模型推断的关系是虚线，标「仅供参考」）、最近一次看到的时间；从这里去处理、看经过、问它。
- **地图可以滚轮缩放、拖动**；`Esc` 先关面板，再回到全貌。
- **「经过」页从哪里进来就回到哪里**（待决、现场、全景）。

## 全景的两种看法和数据准确（2026-11-11）

**主人的两句话**：先是「查一下 knowledge-graph-3d.tsx 这个库，看看我们是否可以拿来借鉴一下？且做一个 Preview」；看过预览之后：「**保留 2D 与 3D 两种 View，更重要的是，保证数据的准确性**」。

**怎么看**：打开 `index.html`，按 `3` 进全景，按 `V` 在平面和 3D 之间切（或者点左上角的「平面 / 3D」）。地址 `index.html#/world/3d` 直接进 3D。截图在 `docs/images/new-ui-face/world-2d-3d/`（14 张）。

### 两种看法是同一个视角

不是两个页面。一份状态（搜的什么、筛的什么、选中了谁、几点钟、是不是在找路），一套面板，两种画法：

- 该亮哪些资源、哪些有环、哪些带名字、路径是哪几步，只在一个地方算：`NF.world.scene`（`model-world.js`）。平面图（`sky.js`）和 3D（`sky3d.js`）都只是把这份结果画出来，自己不做任何判断。面板上的数字也从这一份里取。
- 切过去的时候，选中的资源、筛选、时间、路径都原样带过去，镜头对着同一个东西。
- 3D 引擎只有第一次切到 3D 时才加载（`vendor/`，1.4 MB）；不切就不加载，原型的其他部分仍然是零依赖。
- 按键两边一样：`F` 找、`G` 只看它周围、`L` 找路、`P` 回放、`[` `]` 按事件跳、`0` 回到现在、`H` 回到全貌、`Esc` 一层一层退；3D 多一个 `R` 自动旋转。

### 数据准确：定下来的规矩

1. **一个事实只有一个出处。** 两种看法、每块面板、每个数字，都从同一份结果里来。不允许某个看法或某块面板自己再算一遍。
2. **画出来的要和数据对得上，而且要查。** 每次变化之后，页面去问屏幕上的那个看法「你实际画了什么」——平面图是画的时候数出来的，3D 是从引擎自己的物体上读回来的（多少个球、多少个是亮的、多少条线、多少个环和名字）——再和结果逐项比。左边的「数据核对」写着比的结果；对不上就变红，并说出是哪一项、应该是多少、画出来是多少。
3. **数字之间的关系要说清楚。** 「9 个资源不正常」和「16 件事在等你」不是一回事：页面写明这 16 件里 8 件在图上有环，1 件的资源现在已经正常（在等验收），7 件不对应图上的任何资源；另有 1 个环是 agent 在处理的事。
4. **不知道的不装作知道。** 没有未结问题是「未知」，不是「健康」。模型推断的关系单独标出（平面是虚线，3D 是弯线），不画方向。位置是按账户和区域排的，图例里写明「不是网络拓扑」。
5. **方向只在有方向的地方画。** 关系从上游到下游（容器到成员）；流动的点只出现在选中资源的连线上，沿着这个方向走。模型推断的关系方向未知，没有点。资源面板里每个邻居标明是上游还是下游。
6. **连得上不等于会传过去。** 「找路」给的是两个资源怎么连着（最短的那条、隔了几步、连不到就说连不到），页面写明「不代表故障一定沿着这条路传」，路径上不画流向。
7. **数据是什么时候的，写出来。** 「资源和关系是 06:08 UTC 那次扫描的结果，之后的变化还不在图上。」回到过去时写明哪些是按那个时刻算的、哪些用的是现在的。
8. **不见了的资源既不当成还在，也不悄悄消失。** 画成虚线空心圈、名字划掉，不算进「在看着的资源数」；面板写明最后一次看到的时间，以及「这不等于它被删掉了」。回到它还在的时刻，它就还在。
9. **失败不是空，空不是健康**（D1 起的规矩）：取不到数显示「—」，不显示 0。

### 这套核对查出了什么

把 3D 接进来的当天，核对就拦下了 3D 看法里的两个真问题（平面图一路都是一致的）：

- 筛选或只看周围时，不见了的 3 个资源在 3D 里被画成了普通的暗点——「已经不见了的资源应为 3，画出来是 0」。
- 换到另一个时刻或退出找路之后，3D 里上一次留下的环和名字还在被计数——「环应为 6，画出来是 9」。

两处都已改掉。另外做了反向的验证：故意让一个看法少画一个环、或者把三个球弄暗，核对都报了出来（截图 13）。

### knowledge-graph-3d.tsx 是什么，借鉴了什么

它不是一个库，是你另一个项目里的组件：`Nexus-AI-strands/BeOne-nexus/nexus-ai/web/src/components/avatar4/knowledge-graph-3d.tsx`，1,267 行，React（Next.js），画的是数字分身的知识图谱。底下用的库是 `react-force-graph-3d`（^1.29.1）和 `three`（^0.184.0）。我们的 3D 看法用的是同一个引擎（`3d-force-graph` 1.80.2，前者是它的 React 外壳）。

| | 内容 | 在我们这里 |
|---|---|---|
| 借 | 两个资源之间找路 | 两种看法都有（`L`）。加了一句「不代表故障一定沿着它传」 |
| 借 | 只看它周围 | 两种看法都有（`G`） |
| 借 | 连线上流动的点 | 只在选中资源的连线上，只沿着已知的方向 |
| 借 | 邻居按关系分组 | 资源面板里标上游 / 下游 / 所属 / 包含 / 跨集群 / 模型推断 |
| 借（D4） | 「调查」带着上下文去对话；地址直接定位到某个资源 | 放到 D4 |
| 借（以后） | 资源的出现和消失进回放 | 现在回放里已经有「不见了」；出现还没有 |

### D4 检查时发现并改掉的

- **指令条的回车也传到了页面本身**（旧指令条就有）：在经过页上用指令条打开一件事，回车会立刻又把页面退回去。现在指令条和输入框自己的键不往下传。
- 结果列表里的小字是 10–10.8 px（旧指令条的按键提示也是），低于 12 px 的规矩。现在是 12 px。
- 手机宽度：顶栏多了第四个视角和「通知」之后宽了 15 px（英文 57 px）；对话列表把整列撑到了 654 px。现在「通知」「昼夜」在手机上是图标，`?` 收进命令清单，列表不再撑宽。
- 示例数据：不再等的 5 件事起初是从在等的事复制的，I#9 的经过页上诊断写的是 RDS 的备份 —— 现在每件都有自己的记录；忽略的理由原来一律记成「现在」的时间。
- 被拒的附件原来出现在已经发出的消息里。产品是在上传那一步就拒绝的，现在它只留在输入框里。
- 打开一段对话原来滚到最底，最后那个问题被切掉了。现在停在最后一问的开头；回答进行中才跟着往下。
- 还在做的那一步显示了一个时长。
- 从经过页打开的对话，`Esc` 回到了待决而不是经过页。

D4 里没有做的：示例对话的英文（D7）；通知历史里决定的说法是照提示原样记的（「已批准 I#8，5 秒后开始执行」），D7 改成过去时；「存成报告」打开的报告页（D5）。
