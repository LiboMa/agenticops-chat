### 已经定下来的做法

- **色板**：两套主题下每一种文字色在每一种底色上都 ≥ 4.5:1（`gallery.html` 现算，`selftest.html` 断言）。正文和标签不小于 12px。
- **两种功能色**：琥珀 = 在等人；青绿 = agent 在做、代码核实。红只给「严重」，紫给「变更」。
- **不用模块**：普通 `<script>`，全局命名空间 `NF`，双击 `index.html` 在 `file://` 下就能跑（已验证）。
- **逻辑和界面分开**：`NF.createStore(seed, clock)` 不碰 DOM；每个决定都走 `store.act()`，5 秒内可撤回，新的决定会让上一个立即生效。
- **简报是注册表**：`NF.briefs[kind] = {ask, body, buttons, primary, reject, keys}`。11 种简报盖住 15 种情形（对照表见下）。
- **队列的顺序**：先按严重度，再按等待时间，和后端 `sort=severity` 的排法一致；顶部一排筛选（全部 / 批准 / 验收 / 确认 / 异常），分组和后端的 `DECISION_OF` 一致。
- **每页简报开头一句「需要你做什么」**（琥珀色的一行），然后才是内容。
- **`A` 永远是这一页的主要动作**；只有会改动基础设施的（批准并执行）才需要按住。
- **撤回之后焦点回到被撤回的那件事上。**
- **四种数据状态**统一画法；计数取不到时显示「—」，不显示 0。
- **时间一律 UTC**，并写明「UTC」。
- **原型开关**（左下角，虚线框，不属于产品）：数据状态、身份、语言、主题、重置。

D2 加的：

- **说「不」有两种**，共用一个理由框，都必须写理由，都可以 5 秒内撤回：
  - `R` **要求修改** —— agent 按你那句话重做方案，新版本回到你这里，标出和上一版差在哪几步。
  - `D` **忽略**（问题）/ **拒绝**（变更）—— 到此为止。问题记为 `dismissed`，同一来源的新信号并进它、不再提醒，之后可以在「经过」页重新打开；变更记为 `rejected`，要做得另提一张。
  - 只在「有方案或诊断要判断」的简报上有 `D`。验收必须给结论，批准了没开始的只能重试或撤回批准。
- **事情会回到你这里**：交给 agent 的事做完后以新的情形回到队列（要求修改 → 新方案待批准；批准 → 执行 → 有检查没结果就回来验收；确认诊断 → 方案待批准；变更送审 → 待批准），顶上一行说明它为什么回来。
- **「经过」页**（简报右上角，或按 `Enter`）：六步时间线（问题：发现、诊断、方案、批准、执行、验收；变更：申请、审核、方案、批准、执行、验收）。圆点五种：做完、现在、出错、停在这里、还没到。方案的每一步和每次执行可以展开。右边是事实（含后端状态的原名）和只能追加的备注。
- **状态栏说三件事**：后端状态的叫法、在等谁、账户和区域。「在等谁」按这件事此刻的实际情况算（`NF.waitsOn`），不是按状态查表 —— 同一个 `fix_planned`，方案待批准时在等你，方案被要求修改时在等 agent。
- **后端状态的对应关系对着代码核过**（`models.py` 的三张转移表、`services/work_phases.py`）：方案被退回时问题留在 `fix_planned`；撤回批准后问题回到 `root_cause_identified`，变更是 `cancelled`；`acknowledged` 等的是 agent。
- **只读账户看得到每一页，但页面上没有任何可以动手的控件**（动作按钮、打勾框、判断按钮、回答框、备注框都不画）。
- **位置（7 / 16）在简报的抬头**，动作条里只有动作：主要动作实心，其他决定凸起，「问它 / 稍后 / 忽略」是透明底。
- **屏幕上没有小于 12px 的字**（D2 把按键提示和时间刻度从 11.5 / 10px 提到了 12px）。

## 预览 1：这次看什么

打开 `index.html`（双击即可）。左下角「原型开关」可以切数据状态、身份、语言、主题，「重置」回到最初的 16 件事。

1. **队列和筛选**：16 件事，先严重度后等待时间；顶上五个筛选。`J` / `K` 换一件。
2. **15 种情形各一页**：对照上面的表逐页看 —— 每页第一行是「需要你：…」，`A` 是这一页的主要动作。
