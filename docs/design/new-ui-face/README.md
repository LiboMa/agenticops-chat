### 已经定下来的做法（D1）

- **色板**：两套主题下每一种文字色在每一种底色上都 ≥ 4.5:1（脚本算过，数值写在 `proto.css` 顶部的 token 里）。正文和标签不小于 12px。
- **两种功能色**：琥珀 = 在等人；青绿 = agent 在做。红只给「严重」，紫给「变更」。
- **不用模块**：普通 `<script>`，全局命名空间 `NF`，这样双击 `index.html` 在 `file://` 下也能跑。
- **逻辑和界面分开**：`NF.createStore(seed, clock)` 不碰 DOM，时钟是注入的，`selftest.html` 用假时钟测它。
- **简报是注册表**：`NF.briefs[kind] = {ask, body, actions}`，`NF.actions[...]` 是对应的逻辑。D2 再加 8 种。
- **队列的顺序**：先按严重度，再按等待时间；顶部一排筛选（全部 / 批准 / 验收 / 确认 / 异常）。不再按「等得最久」排。
- **每页简报开头一句「需要你做什么」**（琥珀色的一行），然后才是内容。
- **`A` 永远是这一页的主要动作**；只有会改动基础设施的（批准并执行、重试执行）才需要按住。
- **四种数据状态**统一画法（`.state` / `.skel`）；顶栏的计数在加载失败时显示「—」，不显示 0。
- **原型开关**（左下角，虚线框，不属于产品）：数据状态、身份、语言、主题。
- D2 的示例数据会有 16 件事，覆盖 15 种待办情形（问题 10 种 + 变更 5 种）。
