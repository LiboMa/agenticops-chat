### 已经定下来的做法

- **色板**：两套主题下每一种文字色在每一种底色上都 ≥ 4.5:1（`gallery.html` 现算，`selftest.html` 断言）。正文和标签不小于 12px。
- **两种功能色**：琥珀 = 在等人；青绿 = agent 在做、代码核实。红只给「严重」，紫给「变更」。
- **不用模块**：普通 `<script>`，全局命名空间 `NF`，双击 `index.html` 在 `file://` 下就能跑（已验证）。
- **逻辑和界面分开**：`NF.createStore(seed, clock)` 不碰 DOM；每个决定都走 `store.act()`，5 秒内可撤回，新的决定会让上一个立即生效。
- **简报是注册表**：`NF.briefs[kind] = {ask, body, buttons, primary, reject, keys}`。D2 再加 8 种。
- **队列的顺序**：先按严重度，再按等待时间，和后端 `sort=severity` 的排法一致；顶部一排筛选（全部 / 批准 / 验收 / 确认 / 异常），分组和后端的 `DECISION_OF` 一致。
- **每页简报开头一句「需要你做什么」**（琥珀色的一行），然后才是内容。
- **`A` 永远是这一页的主要动作**；只有会改动基础设施的（批准并执行）才需要按住。
- **撤回之后焦点回到被撤回的那件事上。**
- **四种数据状态**统一画法；计数取不到时显示「—」，不显示 0。
- **时间一律 UTC**，并写明「UTC」。
- **原型开关**（左下角，虚线框，不属于产品）：数据状态、身份、语言、主题、重置。

## 每阶段的检查记录

### D1（2026-11-11）

| 检查 | 结果 |
|---|---|
| `selftest.html` | 21 / 21 通过（`http://` 和 `file://` 下都跑过） |
| 脚本错误 | 0（1440×900、1024×768、390×844，三个视角和全部流程） |
| 横向溢出 | 0（三种宽度 × 三个视角；一览页也是 0） |
| 对比度 | 两套主题 28 组「文字 × 底」+ 主按钮，最低 4.53:1（夜间：标签色在抬起的面上） |
| 键盘 | 全流程只用键盘走通：按住 `A` 批准 → `Z` 撤回 → 再批准两件 → `Y` 判断 → `X` ×3 + `A` 验收 → `R` 退回并写理由 |
| 撤回 | 撤回后状态复原、焦点回到原处；连续批准时前一件立即生效；撤回期过后才开始执行 |
| 四种数据状态 | 加载中计数显示「…」，失败显示「—」并给出上次成功的时间，空和「全部处理完」是同一页 |
| 只读身份 | 没有任何动作按钮；按住 `A`、按 `R` 都不起作用 |
| 英文 | 界面文字全部切换（示例数据仍是中文，D7 补） |
| 减少动态效果 | 换页和骨架动画关闭；「按住批准」的填充保留 |
| 截图 | `docs/images/new-ui-face/d1/`（21 张） |

D1 里没有做的：「现场」和「全景」的四种数据状态（D3）、未登录的样子（D6）、示例数据的英文（D7）。
